# 快速成谱交付与协作记录

更新：2026-10-17。本文件由产品设计 agent 维护；产品需求与指标以 [README](../README.md) 的确认状态为准。用户已授权产品设计与产品开发两个 agent 持续协作，更新后的授权允许实现，不再受此前仅讨论的阶段限制。候选质量、速度与玩家指标仍未自动获批。

## 当前交付边界

先完成可以实际运行和检查的闭环：**本地音频 → 选择定轨／无轨 → 生成整曲 → 音频同步视觉预览 → 导出谱面及诊断报告**。这是一项范围有限的工程里程碑，不代表整个产品、声学质量或真实可玩性已经验收。

- 定轨：固定四位置，保留 Tap / Drag / Hold / Flick；单独检查、报告和导出。
- 无轨：先交付静态单判定线 free-x，同样保留四键型和多指样本；动态判定线与演出模型保持后续独立里程碑，不以静态预览替代。
- 优先复用现有模型权重。首轮显示“基线谱”，不提供没有训练／评估证据的难度档位。
- 首轮提供本地命令入口与独立预览文件，不引入云服务、账户、付费、部署或大规模训练。后续逐步降低使用门槛。
- 预览用于检查音频、落点、键型、时长和整曲呈现，不具有真实播放器的输入判定与手感验收含义。
- 暂定 WAV／OGG 为已有实测格式；其他格式逐项实测后扩展。当前分析模块的 600 秒上限是实现边界，不能替代全链路实际支持范围测量。
- **BPM 暂需显式提供。** 现有 AR 生成受节拍时基影响；未实现 BPM 推断，不能把固定 120 标成估计结果。报告记录 `timing_source=provided`。这是基线限制，后续必须解决上传音乐后自动成谱的使用门槛。

| E3 | 音频同步预览：播放、暂停、跳转、重播 | 预览以音频时钟为主；开始／中段／末尾、跳转后、offset 非零和 Hold 贯穿时段检查 | 待实现；浏览器呈现需实际验证 |
| E4 | 四键型可区分且预览与导出一致 | 检查四种键型、起点、持续时长、位置；用渲染数据与导出事件交叉核对，不能仅看文件存在 | 待实现 |
| E5 | 稳定 ID、原始／最终输出与修改日志 | 抽样跟踪原始音符到最终导出；删除、移位、截短可解释，模型收益和修复收益分列 | 待实现；不引入 Hold 配额 |
| E6 | Phigros v3 JSON 及可打开的本地交付物 | JSON 格式和全时间轴校验；预览不依赖 CDN；音频引用可用；重复执行不污染先前结果 | 待实现；目标播放器兼容另验 |
| E7 | 真实整谱回归与可复现交接 | 初轮至少 3 首不同特征的完整曲 × 2 模式；涵盖短／长、密集／稀疏，不能只展示一段或优选谱 | 待执行；小样本不等于冻结质量测试 |

各失败路径只做足以验证行为的有意义测试；不制造真实磁盘耗尽或 OOM。目标资源线沿用现有保护，不因一次小样本运行成功自动放宽。并行生成应等待资源测量，默认串行以控制峰值。

## 独立审查口径

交付先提供固定提交、复现命令、逐曲结果和已知限制，再审查行为。所有检查记录“通过／缺陷／待证据”，不把“尚未验证”改写成通过，也不把尚待产品选择的部分判为代码缺陷。

当前工程审查逐项证据见 [产品审查记录](product_review.json)。已独立复现“候选全部覆盖但末和弦仍因 token 预算被截断”的完成状态缺陷，开发正在修正；资源错误、失败状态与声学质量按各自证据记录。

| 维度 | 本轮可自动验收 | 仍需外部／后续证据 |
| --- | --- | --- |
| 时间 | 音频绝对秒、tick、BPM、offset 往返；整曲尾部；无重复减 offset | 实际设备音频延迟及目标播放器时钟 |
| 声学 | 版本化候选接入、分块尾段和概率保留、来源标记 | 审核声学标注、独立校准及冻结测试；不能借用旧全曲 F1 |
| 成谱 | 两种模式都可运行；非法时间、时长、位置等硬错误为 0 | 玩法判定规则与实际目标播放器导入；音乐对应和人类可玩性 |
| 预览 | 音频时钟驱动、跳转后状态、四键型与 Hold 呈现 | 用户是否认为视觉清晰、真实操作和手感；Canvas 自动播放不是试玩 |
| 操作限制 | 无通用双指上限；任何接触预算显式记录 | 不同设备的真实多指操作、Drag／Flick 判定及动作语义 |
| 速度与资源 | 阶段耗时、峰值 RAM／GPU、磁盘增量、失败与任务回收 | 固定硬件和样本量下的 P50/P95；未确认的 60 秒目标不能自动生效 |
| 质量提升 | 对照配置冻结、逐曲可比、修复负担分列 | 经批准的接受门槛、冻结独立歌曲、盲测与真人完整试玩 |

音频理解 `2965310` 的模块新增 29 项测试已由主会话分批复验；完整 209 项是实现会话报告。Eltaw 单曲两模式的产物和审计文件已存在，但其生成报告记录的是提交前工作树及源文件哈希，发布验证需说明版本对应关系。以上证据只支持该样本上的接口／格式行为，不支持声学准确率或可玩率结论。

## 后续工作顺序

当前工程闭环通过后，设计 agent 必须继续审查下一阶段，不能把一次评审结束当作产品完成。

| 顺序 | 工作 | 推进条件与完成证据 |
| --- | --- | --- |
| N1 | 降低快速成谱使用门槛 | 在现有闭环上选择本地交互入口；检查 BPM 对模型的影响；实现并测量自动时基／节拍方案，明确不确定时如何处理 |
| K2 | 定轨取音、难度和轨道动作改善 | 定轨独立固定基线、错误音频对照、原始冲突和修复负担；保持四键型；不以键型比例达标 |
| F2 | 无轨取音、难度和空间动作改善 | 无轨独立基线，保留多指；按显式操作配置衡量位置、Hold 占用与移动，并验证音乐对应 |
| S2q | 声学标注、校准与模型质量 | 先固定可听辨事件标注协议与来源划分；原谱取音和声学标签分开；声学目标数值待用户确认，不阻塞已有基线的工程闭环 |
| F4–F5 | 动态表示、可控演出、演出模型 | 有效演出标签和坐标变换；保持击打语义；先可控基线，再验证学习模型；模板不算模型完成 |
| Q1 | 目标播放器与设备体验 | 明确目标程序／版本、输入语义和设备；做导入、完整播放及真实操作；形成完整曲目和失败清单 |
| Q2 | 产品质量冻结与稳定发布 | 定轨／无轨分别通过已确认门槛；冻结测试、真人试玩、资源回归与集成证据齐全后才进 `main` |
| L1 | 后续编辑工作流 | 快速成谱交付后再实施逐音编辑、局部重生成、演出编辑与版本保存 |

## 可以自主决定与需要用户把关的事项

可以自主推进：本地单用户串行基线、复用现有权重、独立预览与 JSON 导出、资源保护、正确失败语义、工作区和分支拆分、可逆的 CLI／文件布局、测试与修复。阶段实现不代表候选模型或数值永久成为默认。

需要用户决定、但目前不阻塞工程闭环：最终目标播放器和设备／输入语义；动态演出是否作为首版发布必选；正式支持音乐范围；质量与等待时间承诺；所需玩家试玩组织。若待决事项阻塞下一阶段，先提交可审查的选项及影响，而不是把所有待定项同时抛回用户。

无法靠两个 agent 自动补齐的证据：独立的人类声学标注／复核、玩家完整试玩与主观体验认可。可以准备工具、样本和量表并继续其他工作，不能伪造这些结果，也不能宣称产品已完成。

## 协作协议与恢复入口

- 主会话：整合用户决定、资源调度、最终交付和跨分支集成。
- `/root/product_design`：维护 README 与本交付／验收记录；只读实现；独立复现缺陷；向开发 agent 发编号、严重性、证据和再验收条件。
- `/root/product_development`：隔离工作区完成实现、验证与推送；逐项响应；提交下一批可审查交付，不并行改产品文档。
- 两个 agent 通过协作消息直接沟通；提交、任务、证据仍写入文档，避免上下文压缩后丢失。消息传递只在本次活动会话中有效，不承诺结束会话后自动醒来工作。
- 循环：需求／验收 → 固定范围实现 → 交付证据 → 独立审查 → 修复并复验 → 标记该项通过 → 推进下一项。遇到实质产品取舍交主会话，不重复索要已有授权。
- 每次恢复先读 README、本文件、`docs/implementation_review.json`、开发交付报告及 Git 状态。尚未通过的工程、模型质量和人类验收分别保留，不因压缩或分支推送而自动关闭。
