# 无轨动态演出：最小表示、学习基线与验收

状态：2026-10-17 的实施设计，尚未实现。归属 `feature/freeform-gameplay`。本文件细化 README 的 F4–F5；静态 free-x、动态格式链路、学习式演出和真实试玩分开验收。动态是否为首版发布必选仍待用户决定，不阻塞当前快速成谱入口。

## 数据能提供什么

现有 300 份原始 ID JSON 包含音符归属、各条线的 BPM、移动、旋转、速度和显隐事件，可用于学习音乐／玩法条件下的演出参数与曲线。294 份 v3、6 份 v1；训练 270 份均有动态事件。`generate.json` 是静态派生谱，不能充当演出真值。

只读结构清点得到 5510 条原始线，其中 1762 条没有音符。空线可能用于装饰，也可能只是闲置占位，不能按“无音符”全部删除。原始、未裁剪事件还包含 5900 个零时长区间、44 个反向时间区间、7 个相邻间隙、84 个相邻重叠；值域为旋转 −9999～9999、显隐 −1～5、速度 −9999～100000，其中负速度事件 7947 个。**这包含哨兵和音频外状态，不等于播放域内有同样数量的错误。** 首先需要按有效时间与目标解释规则审计，不能把值简单截到惯常范围后伪称保留原谱。

现有 `mine_chart()` 只在音符头、Hold 尾求线状态，足以形成部分击打几何标签，不包含全程可见性、进场轨迹、速度积分或 Hold 中间轨迹。其事件间隙 fallback 也不适合作新的全时间解释器。旧设计中的“无损玩法”“保底可玩”等描述不作为本轮结论；端点落在屏幕内不能证明中间过程可玩。

## F4a：版本化连续时间表示

每首歌保存原始文件与音频哈希、版本、offset、划分和解析版本。保留每条线的原始 ID、BPM、每个音符的上下侧、局部位置、时间、持续、speed／floorPosition 及四类事件；原始文件只读，不覆盖。以查询方式按训练窗口产生标签，先不生成全库高帧率密集缓存。

| 项目 | 表示约定与验收 |
| --- | --- |
| 时间 | 源线原生 tick 与 BPM 保留；`audio_s = native_tick * 60 / (32 * line_bpm) + chart_offset`。线事件在源线原时钟解释，之后转音频秒；不能先统一整数 tick 再推轨迹 |
| v1／v3 | v3 的 x／y 与 v1 的打包坐标分别解码；负值取整／余数语义、边界和空事件列表需显式测试，不能仅依赖语言默认 `%` 行为 |
| 事件边界 | 明确接缝归属、零时长跳变、间隙、重叠、音频前后哨兵的处理；无支持语义时列入诊断／排除记录，不静默改曲线 |
| 旋转 | 保留原始连续角度与转数；不能逐点包到 ±180° 后把一整圈抹去。周期角度与运动方向分别检查 |
| 速度与显隐 | 同时保留源值和解释后的状态；按分段速度积分恢复落距。负速、超常显隐值先核对解释，不直接视为坏标签或夹到正值／0～1 |
| 线有效性 | 保留玩法线与 `visible_decoration_candidate`／`idle`／`unknown`。原 JSON 不含完整纹理与实际线长时，只报 alpha 与规范无限线相交的 `potential_visible`，不承诺实际渲染可见；有限采样未见只能叫 `sampled_not_visible`，不能证明全程闲置。记录掩码和原 ID，模型线槽编号不直接当通用语义 |
| Hold | 保留头尾时间与整段几何目标轨迹；采样包含全部相关事件边界与内部检查点，支持跨窗口持续状态 |
| 屏幕 | 首轮用明确的 16:9 规范视口，左下为 (0,0)；渲染可留边适配。不能把屏宽单位直接当成屏高单位 |

差分解释参考固定为 Phira 提交 `a22ea8958410ac940adec83b54bbf4e6b293d191`，不使用可变的 main 内容。[PGR 解析器](https://github.com/TeamFlos/phira/blob/a22ea8958410ac940adec83b54bbf4e6b293d191/prpr/src/parse/pgr.rs)的 SHA-256 为 `7a3ca75e40c3756adfde21ecac86f1c1888a659aac8b596844c7d057d8254c22`；解析、插值、坐标变换与音符呈现所用 8 个小文件的固定 URL、大小及哈希见 [参考清单](phira_reference.json)。只读源码参考不等于选定产品播放器，也不证明与官方游戏语义完全一致。

差分样例特别覆盖 v1 负余数、旋转方向与规范坐标、Hold speed 以及源 floorPosition 和积分重建的差别。该参考会修改速度首段起点、丢掉部分曲线的末 keyframe，并用最晚音符头加一秒作为高度积分末端；因此单段非哨兵事件、末尾长 Hold 等边界需要单独审计。参考自身行为、规范分段曲线和最终目标播放器实测应分别报告，不能把移植参考后的自洽结果当作官方真值。

F4a 先用小型受控样例验证：静线、平移、±90° 与整圈旋转、两条不同 BPM 线、非零 offset、v1／v3 等价姿态、事件接缝／空列表／间隙／重叠、负速／显隐状态及 Hold 跨事件。再取原始真实谱检查完整时间轴。结构合法与解释可重建分别报结果，不把不支持样例悄悄移出分母。

独立数值样例的预期先写清，避免只测试实现自洽：

| 样例 | 规范数学预期与检查目的 |
| --- | --- |
| 两线时钟 | offset=0.25 秒；120 BPM 的 tick=32 与 240 BPM 的 tick=64 都落在音频 0.75 秒。前者 Hold 持续 64 tick，应结束于 1.75 秒 |
| 连续整圈 | 0～2 秒角度从 0° 变为 360°，1 秒应为 180°；不能因头尾姿态相同把整个区间解释成 0° |
| Hold 中间越界 | 线心 (0.5,0.9)、局部 p=2，0～2 秒旋转一圈。头尾判定点 (0.6125,0.9) 均在屏内，0.5 秒却到 (0.5,1.1)；只看端点或中点会漏掉越界 |
| 负速度积分 | 0～1 秒速度 2，1～3 秒速度 −1；原始滚动单位积分在 0／1／2／3 秒为 0／2／1／0。参考的 HEIGHT_RATIO 缩放另列，不能混用单位 |
| v1 负打包值 | −1001 按截向零的除法与有符号余数得到 x=−1、y=−1，再除以 880／520；Python 非负余数会得到不同 y，不能默用 |
| 非哨兵末段 | 唯一一段 0～2 秒从 0 变到 10，规范 1 秒值为 5；参考转换的末 keyframe 移除可能产生差异，必须单列而非修改规范预期 |

这些是公式／固定源码推导的验收夹具，尚未运行差分。最后一个长 Hold、末 keyframe、空列表和重叠等参考差异还需实际输出与解释诊断，不能据表格宣称兼容通过。

## F4b：不能随意给静态玩法叠动画

在规范视口中，线中心为 `(Lx(t), Ly(t))`，角度为 `θ(t)`，音符局部位置 `p` 固定时，其线上的几何目标为：

```text
qx(t) = Lx(t) + 0.05625 * p * cos θ(t)
qy(t) = Ly(t) + 0.1     * p * sin θ(t)
```

当前 free-x 只给横坐标与固定高度。对同拍两个不同横坐标、相同高度的目标，如果要求仍共用一条线并保持世界判定点，该线在判定时刻必须穿过两点，不能任意旋转。改变一条共享线的平移／角度，通常会同时改变多个音符的位置。

给定线姿态后，可以对世界目标反求局部 `p`，但还须检查目标在线上；投影得到一个数值不代表几何可行。若不可行，应改线分配、限制演出或明确升级二维玩法，不能悄悄移动判定点。多线数量与玩家手指数是不同概念。

Hold 更严格：一个固定世界目标的 Hold，可由绕该点运动且满足方程的专用线表示；多个不同固定目标的 Hold 同时共线时，进一步限制线的姿态。只让头尾重合，不能保证中间不绕远、越界或突然跳转。这里的轨迹是判定几何目标，玩家是否必须跟随及允许的触摸范围仍取决于实际判定器。

因此明确两种契约：

1. **玩法保持演出**：音符身份、time、type、duration、同刻关系严格保留；全部击打世界位置，以及声明需保留的 Hold 全程几何轨迹也保持。演出只使用剩余自由度，或合法地重新分配判定线。任何投影／限制都记录修改量。
2. **联合玩法与演出生成**：模型可以重新决定二维判定点、Hold 轨迹和线归属，但这是 free-XY／玩法模型升级，需重新验收动作与多指、可见性和音乐对应，不能宣称保持原静态玩法。

首轮可控基线选择契约 1：约束线姿态在击打与 Hold 区间满足目标，必要时分线或固定该段；把机械可行性先验证清楚。静线、手写曲线和模板只是工程对照，不是演出模型交付。若所有预测都被投影回静态，必须报告这种退化，不能因文件含运动事件便宣称实现了有效演出。

## F5：适合现有数据的最小学习基线

先学习一个范围明确的**演出控制模型**，不要求首轮端到端生成任意 24 线原生事件序列：

- 输入为冻结音频时序特征、已生成／参考的玩法事件与 Hold 占用、线组历史；先用小型共享时序网络，沿用资源预算，单项消融。
- 从原始曲线及玩法几何拟合低维、可重建的控制目标，例如局部平移／旋转变化、滚动速度和显隐的分段参数，明确拟合残差和不可表达区间。标签来自原始事件，不把手写模板编号冒充人工风格真值。
- 第一小步可在已知线归属下预测曲线控制，单独标为“已知归属条件实验”；这不等于新音乐的完整演出生成。接入新谱时，还需明确可执行的线分配和约束求解。
- 线组可先按确定性的合法策略建立，以降低训练范围；后续学习“沿用组／新组”或音符同线关系。原始 line_id 只是单谱局部编号，不直接当跨曲分类标签；窗口边界必须维持正在持续的线和 Hold 身份。
- 学到的参数通过 F4b 的可行性求解落为事件。保留模型原始控制、求解后控制及变更原因。只有参数或选择来自训练权重且通过对应实验，才称受限演出模型；纯检索、随机选择或手写模板分别标明。
- 如果契约 1 的自由度不足以表现目标风格，再推进 free-XY 与线归属的联合模型，独立于当前静态 free-x 基线，不能为加动画而无记录地改击打。

训练先在小规模窗口验证标签与学习，再扩大训练划分；每曲按需读取原始事件，不复制数据／权重，不预先渲染全库视频。保留 best／last 两份检查点，记录预估与实测峰值。现有 30 首开发验证曲不作为新的独立最终测试；测试划分与采样必须按音频来源。

| 验收层 | 必须给出的证据 |
| --- | --- |
| 表示与重建 | 源曲线在事件边界和区间内部的重建误差、未支持语义、速度积分及 Hold 轨迹；原始与规范表示可追溯 |
| 机械契约 | 两种契约分别验证；玩法保持时无未声明 time／type／duration／世界目标变化，Hold 检查全程；原始控制与求解修正分列 |
| 确实学习 | 训练／开发曲独立；学习模型对比静态、固定均值／模板、无音频／错误音频控制。固定玩法换音频检查音频条件是否有效，不用训练 loss 下降代替验收 |
| 运动表达 | 原始线状态与导出状态差异、动态覆盖、连续性和求解投影比例；静态退化必须显示，模板数量与线数不是质量指标 |
| 完整流程 | 新音乐→玩法→演出模型→多线导出→完整动态预览；已知原谱归属的重建任务不能冒充该流程 |
| 产品体验 | 目标播放器导入、关键音符可见性／进场读谱、Hold 与多指的实际操作、音乐呼应和完整歌曲试玩；两个 agent 不能替代玩家认可 |

上述几何数值误差用于解释器与求解器的数值正确性，不是人体反应或视觉舒适阈值。主观质量和速度承诺沿用 README 的待确认状态，不从原谱值域直接推导“安全范围”。
