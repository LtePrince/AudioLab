## 当前28维历史摘要

定义在 [chart_history.py](../src/models/chart_history.py)。它不是28个token，而是每个谱面token旁的一组28个数；取值只依赖此前已经处理的token，在观察当前输入token之前计算。训练用参考历史，生成用已生成历史。

| 维度（从1计数） | 字段 | 含义 |
| --- | --- | --- |
| 1 | has_previous_note | 此前是否已有音符 |
| 2–4 | previous_x, previous_previous_x, note_delta_x | 上一个、上上个音符的横坐标及两者位移；仅一个时两坐标相同 |
| 5–6 | previous_note_gap_beats, age_beats | 最近两音符的拍间隔；当前token时间距上一音符多少拍 |
| 7 | same_onset | 最近两音符是否同一时刻；不是预测下一音符是否同押 |
| 8 | notes_at_current_onset | 当前时刻已经记录的音符数，除以位置槽数并截到1；当前时间不同则为0 |
| 9–12 | repeat_run, alternating_run, monotonic_run, direction | 最近连续单音组的同轨次数、两位置交替次数、同向移动次数、移动方向 |
| 13–16 | group_delta_x, group_gap_beats, group_gap_change, group_span | 最近两音符组中心位移、拍间隔、间隔比变化、最新组横向跨度 |
| 17–20 | previous_type_tap/drag/hold/flick | 上一音符类型的4维one-hot |
| 21–28 | group_0_x/singleton … group_3_x/singleton | 最近四个同起点音符组，每组的中心横坐标和“是否只有一个音符”标志 |

同起点音符构成一组；组中心是已观察音符的平均横坐标。重复／交替／同向计数遇到多押组即中断，最多查看64组。4K位置用轨道编号除以3归一化；free-x用(bin＋残差)/64。间隔、年龄、次数使用截到64的log1p归一化；间隔变化用log比值除以4再截到[-1,1]，方向为-1/0/1。字段的物理意义不同，28维没有统一的“历史权重”。

摘要不记录Hold当前占用状态或全部Hold时长；时长本身在独立的DUR token中。它也没有把完整历史逐音符复制进去。尽管是有限摘要，早先错误仍可能改变随后很多步的间隔、组信息与模式计数。

## token除此之外包含什么

以E23为准，输入隐向量是256维，相加后仍为256维：

```text
x_i = E(token_id_i)
    + W_time · sinusoid(当前音乐时间, 128维)
    + W_history · history_i[28]
    + W_window · concat(sinusoid(窗口开始), sinusoid(窗口结束))
```

来源：[ChartDecoder.forward/step](../src/models/chart_decoder.py)、[WindowedAR](../src/windowed_ar.py)、[E23架构配置](evaluations/assets/joint_audio_scratch_20261102/architecture.json)。

- **token_id**：普通NOTE直接联合表示轨道与键型，例如“第2轨Hold”；4轨×4键型共16种NOTE。另有BOS、时间锚点、同起点组结束、窗口结束和Hold时长token。因此一个音符不总等于一个token。E23沿用129词表，但起音时间由绝对时间指针＋帧内偏移产生，已不靠旧DT token逐步推进。
- **当前音乐时间**：单独输入，不在NOTE的ID里；使用音频memory帧单位，每帧约46.44ms，支持帧内连续时间。这使模型可区分同一轨道同一键型发生在何时。
- **窗口边界**：本步负责的输出区间，通常10秒；最后一窗上界是实际音频时长。此信息属于任务边界，不是历史模式摘要。
- **序列位置**：self-attention的Q/K还使用RoPE表示token顺序。它与上述音乐时间不同，不是额外拼接进28维的字段。
- **音频**：整曲Mel经可训练编码器得到连续向量，作为另一条memory序列，经cross-attention读取；不是离散词表ID，也不是把音频塞进这28维。编码器和解码器均为6层、8头，且音频编码器本身有双向self-attention。

解码器每层用因果self-attention读取此前token，再用cross-attention读取整曲有效音频。当前A模型没有额外soft起音通道。当前代码也没有独立BPM嵌入：BPM用于摘要的秒/拍换算，以及Hold tick与秒的转换。训练时token_dropout=0.15会同时丢弃该步的token嵌入与摘要投影，保留时间和窗口条件；推理时不启用。

因此当前存在两条历史通路：历史token通过self-attention；手算摘要通过输入投影。错误历史可沿两条通路传播，28维多不等于它必然占主导。

## 新版本提议与归因边界

| 预登记身份 | 拟改变 | 状态 |
| --- | --- | --- |
| AL-AR4K v0.8.0 / A-SA / E25 | 移除手工摘要投影与输入，保留历史token、音乐时间、窗口边界、音频cross-attention；无独立BPM嵌入 | 仅提议，未实现、未训练、无权重 |
| AL-AR4K v0.9.0 / A-SA-BPM / E25 | 同上，并增加单独的BPM条件 | 仅提议；是否同时实施两个版本尚在讨论 |

这里“纯self-attention”仅指谱面历史的读取方式；既不删除历史token本身，也不删除整曲音频cross-attention。无显式BPM嵌入也不等于导出流程不再使用BPM。两个版本是并列实验，不代表v0.9一定优于v0.8。

支持尝试的证据是：E16-P0在给定时间与8键前缀的模式任务中，清零摘要后40条新组合仍全部续写正确，而只保留当前token、保留摘要时整段正确为0/40。这只证明该受控任务确实利用self-attention；清零旧权重输入不能替代无摘要模型的重新训练。E24自然歌曲归因中，缩短self-attention历史与清零当前摘要均能改变误结束，同时也能产生退化，尚不能确认“摘要是主因”。

后续比较应使用同一批全300首、同一数据顺序、预算、输出协议和解码设置，编码器与解码器均可训练，分别从随机初始化训练；共享张量需核对一致，不能只依赖相同seed（移除模块会改变随机数消耗）。单独比较参考历史与生成历史下的时间、键型、误结束和有参考空窗，兼顾静音多出音。新增BPM条件与E24建议的恢复训练分开，避免同时改变多个因素后无法归因。训练预算、BPM条件形式及两版本是否同时执行均尚未定稿。
