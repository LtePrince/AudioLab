# Phira 首版交付与触屏试玩

用户已确认首个实际播放器为 **Phira＋手机／平板触屏**；首版为定轨四个固定触屏位置与静态 free-x，两者保留 Tap／Drag／Hold／Flick 和多指。Hold 不设数量配额。学习式动态表演按 F4b／F5 后续推进，不作为首版发布必要项。

生成端已确认为用户的另一台Linux＋NVIDIA个人PC；当前机器只开发验证。个人PC克隆代码、安装依赖与独立权重包后，通过该PC的回环网页／CLI生成并下载完整谱包，再传到移动设备本地导入。网页音频同步预览用于检查候选，实际击打在Phira完成。开发机localhost不是个人PC部署结果，4K不附带键盘映射。

## 工程交付范围

开发采用 Phira 官方发布 **v0.8.2** 的源码提交 `c830dee5e07a2b8f06104576f30d8045e0859aa7` 核对导入与时间语义；源码依据和文件哈希随实现记录。它与 F4a 解释器使用的开发提交 `a22ea8958410ac940adec83b54bbf4e6b293d191` 分别记录。选定源码参考不等于已经安装该版本或完成手机实测，试玩须填写设备上的实际版本。

该版 [PGR 解析器](https://github.com/TeamFlos/phira/blob/c830dee5e07a2b8f06104576f30d8045e0859aa7/prpr/src/parse/pgr.rs)将音符时间转为 `native_tick × 60 / (32 × line_bpm)` 秒并保留 chart offset；[游戏时钟](https://github.com/TeamFlos/phira/blob/c830dee5e07a2b8f06104576f30d8045e0859aa7/prpr/src/scene/game.rs)使用 `max(0, audio_time − chart.offset − info.offset − device_offset)`。因此包内 `info.offset=0`、设备时差为零时，已知音符的音频时刻仍为原生秒时刻加 `chart.offset`；正 chart offset 对应较晚的音频时刻，打包不再次平移音符。这里只核对固定源码，设备时差由实际试玩另记。

每种玩法独立下载一个完整 ZIP，包含 `info.yml`、`chart.json`、音频、默认封面和 AudioLab 来源说明。谱面与音频保持选定最终产物的原字节；谱包离开工作区后仍能使用，不能依赖本机软链接。默认封面有明确自有来源，未提供的音乐作者不填成 AudioLab；没有评定的难度显示“未定级”，格式所需的数值占位不是模型难度评级。

| 验收项 | 本轮需要的证据 |
| --- | --- |
| PH1 包与来源 | 按固定 Phira 加载规则核对包结构、元数据引用、音频／图片可读取；实际读回 ZIP，成员完整、无外部路径依赖，谱面／音频哈希与选定最终产物一致。两种玩法分别交付 |
| PH2 时间与玩法保持 | 包内 chart 不重写音符时间、offset、四键型、位置和Hold持续；metadata offset 使用明确的零值，避免对 chart offset 重复补偿。非零offset夹具核对源码时钟公式；四位置和静态free-x分别核对，不新增手数限制 |
| PH3 操作与失败 | 生成完成前完成必要打包和读回；网页下载得到同一包。包装失败不宣称已完成可下载交付，缺文件／写入失败保留明确状态。给已有完成产物补包时写独立目录，不修改冻结输入。只增加所选交付物，沿用8 GiB磁盘／RAM余量保护 |
| PH4 真机与体验 | 将完整包传到手机／平板，记录实际Phira版本、设备／系统、包哈希和时差设置；分别记录导入／完整播放、四键型触摸和Hold／多指片段、音乐对应与可读性反馈。未实际执行的项保持“未执行” |

PH1–PH3可以由源码、文件和浏览器检查验收；PH4需要真实设备和操作证据。源码移植、自动播放、Canvas像素、ZIP能解压均不能替代手机触摸试玩。格式可导入、动作判定正常、音乐性好是不同结论，分别记录；不增加未经确认的分数门槛。

## 最小人工交接

一次交接提供同曲4K包、静态free-x包、简短导入说明，以及必要的已知时间校准包。需要评价R1时另明确标出A/B所用策略与相同音频来源，避免把对照当不同模型。

试玩只需先记录这些事实，失败附曲目／模式／时间位置即可：

1. 设备型号、系统、Phira实际版本、所用包及应用时差设置；能否导入，音乐和谱面是否完整加载。
2. 两种玩法各完成一次整谱播放／实际操作；是否有音画时差、缺尾、四键型无法按预期触发、Hold或多指异常。未完成整谱则记录中止位置和原因。
3. 哪些片段的落点、持续、位置或可读性不合适，以及具体体验；若比较A/B，记录选择与理由，不由程序代填偏好。

小型合成click校准包只用于已知时间、非零offset、四位置／四键型与多指交互检查。它不是模型生成，不计入生成成功率、声学准确率或模型可玩质量；设备时差调整单独记录，整谱对照沿用相同设置，不逐曲事后平移来掩盖时间误差。
