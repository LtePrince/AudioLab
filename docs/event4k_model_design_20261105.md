# Event4K：同步事件输入与版本命名（2026-11-05）

按用户最新要求定义 **AudioLab Event4K / AL-Event4K（同步事件AR）**。同一时刻所有轨道事件构成一个token；保留当前音乐时间和整曲音频，移除28维手工摘要与窗口边界输入，显式BPM做有／无对照。用户随后授权先训练有BPM版本，并确认时间候选与窗口结束共同竞争；实现与预检已完成，实际启动状态见[E26-BPM报告](evaluations/event4k_bpm_20261105.md)。无BPM对照尚未训练，发布权重未替换。

## 模型名与版本号

模型名标识基础输入表达结构。旧 `AL-AR4K` 是逐音符及控制token序列；新 `AL-Event4K` 是逐时刻4×5事件矩阵序列。BPM等额外信息不另起模型名。free-x连续坐标不能直接套用4轨矩阵，本次没有登记虚构的EventFreeX权重。

采用 `模型名 v0.C.R`：

- `C` 是条件配置编号：本次1=无显式BPM，2=有显式BPM，两者都保留时间嵌入。
- `R` 是该配置下的权重修订编号。第一份为0，后续训练、续训、微调或不同seed产生的不同保留权重依次递增；版本号不是效果排名，也不保证各版本是连续训练关系。
- 每份保留、评测或交付的不同参数权重须绑定独立版本、epoch/step、父权重、数据/配置/代码来源与SHA；同一版本不可指向两份不同参数。同一参数的打包、文件重命名或推理采样设置变化不新增模型权重版本，包SHA与参数身份分开记录。
- `latest`、`best`是别名，不能代替唯一版本；临时且未保留的训练中间状态无需制造台账资产。候选版本可以预留，但在权重实际产生前必须是`weights=null`和未训练状态。

| 模型名 | 版本 | 额外条件 | 当前状态 |
| --- | --- | --- | --- |
| AL-Event4K | v0.1.0 | 音乐时间；无显式BPM | 实现支持，尚未启动此组训练 |
| AL-Event4K | v0.2.0 | 音乐时间＋显式BPM | E26-BPM已正式启动全300首从零训练，见运行报告；首份权重保存时绑定此号 |

例如无BPM的第一份保留权重登记v0.1.0，下一份不同权重登记v0.1.1；有BPM对应v0.2.0、v0.2.1。具体轮数与版本的对应在实际保存时登记，不预先把“版本越大”解释成训练更充分。

旧ID继续作为历史别名，避免破坏报告与release。当前两份同结构的联合训练权重新增唯一映射：`AL-AR4K v0.7.1 = 旧v0.7.0 / E22-A / e20`；`AL-AR4K v0.7.2 = 旧v0.7.0 / E23-A / e300`。原v0.7.0保留为历史结构记录。前次未执行的v0.8.0/v0.9.0及E25提议已被本次设计取代；不复用其ID冒充新的训练。

## 一个时刻，一个事件token

令第i个事件时刻为`t_i`，矩阵`E_i ∈ {0,1}^{4×5}`。行是第1–4轨，列固定为：

```text
[Tap, Drag, Flick, HoldStart, HoldEnd]
```

每格表示该时刻该轨该事件是否发生，是多标签二值矩阵。某轨无事件时整行全0，不需要第六个“空键型”。同刻第1轨Tap、第4轨Hold开始：

```text
        Tap Drag Flick HoldStart HoldEnd
轨1      1   0    0       0        0
轨2      0   0    0       0        0
轨3      0   0    0       0        0
轨4      0   0    0       1        0
```

整个矩阵展平后投影为一个稠密向量。Hold结束作为后续时刻矩阵中的HoldEnd事件表示，不再接DUR token；同刻发生的Hold结束和新音符开始一起编码。事件内没有轨道先后推理顺序，不使用一个巨大“所有组合词表”，也不把双押拆成两个NOTE token。

序列为`(t_1,E_1), …, (t_N,E_N)`，包含所有起点与Hold结束时刻的并集；只把原数据同一物理时刻的事件合并，不按F1容差或偏好节拍网格吸附。没有事件的时间用时间间隔表示，不枚举音频每一帧作为空事件。BOS及窗口/整曲结束属于控制协议，不额外拆分一个时刻的音符身份。

输入约定为：

```text
x_i = event_projection(flatten(E_i)) + time_embedding(t_i)
      + optional_bpm_embedding(BPM)
```

谱面历史经因果self-attention读取，整曲音频经cross-attention读取。两组都没有手工历史摘要、显式soft起音通道或窗口边界嵌入；音频编码器和解码器全部可训练。音乐时间使用统一物理时钟，BPM不能替代时间嵌入。

## 输出与窗口

预测下一事件时间，再在该时间条件下输出4×5事件logits，形成一个事件矩阵。事件头可从20个sigmoid概率与多标签BCE基线开始；不能在全部20格上做单一softmax，也不能对每轨五类强制五选一，否则分别无法表达多押或空轨。采样的是整组多标签事件，不在组内再按轨道推进AR序列。

20个独立Bernoulli是概率分解假设，即使共用hidden也不保证捕获所有同刻相关性。需用整组键型匹配和多押组合分布检查，不能仅凭边缘概率宣称“学会双押”。合法事件组合的掩码/采样及相关性建模细节在实现时单独记录，不预设键型比例或双指上限。

窗口边界仅属于外部调度和输出合法域：时间头限制到当前窗及音频有效范围，跨窗继续保留历史、Hold配对状态和整曲音频。**不向token、decoder query或其他隐藏层注入窗口起止值，也不加边界/剩余时长embedding。** 可通过时间候选mask或有界参数化实现，不能把越界预测简单clamp到边界形成堆积。

把边界作为任务条件在数学上可行，但不是分窗必须采取的方式；本版本明确选择只作用于输出。输出结束动作仍须设计并评测：合法范围限制不等于模型已经学会结束；调度器强制推进与模型自主结束必须分开记录。具体结束头与损失在实现报告中固定，不把外部遍历完窗口算成自主EOS。

Hold配对与合法性在编解码/输出检查层维护，不作为手工历史向量喂入网络。尤其需要保留跨窗Hold，以及同轨同刻“旧Hold结束＋新Hold开始”。起音须早于音频末尾，合法Hold尾可以等于末尾。无起点的HoldEnd、重复开启未结束Hold、同一格多次事件等必须明确报告；4×5二值矩阵无法无损表示同格重复或需区分身份的重叠Hold，数据审计不得悄悄合并或删除这类样本。

## 对照和验收

E26登记两组独立权重：无BPM与有BPM。使用同一全300首、相同数据顺序、预算、时钟、窗口、采样与评测；共享参数从相同随机张量初始化。BPM投影单独开关，训练BPM来自相同来源；无BPM组也不额外加入按拍换算的历史摘要。两组导出仍可用相同BPM做格式换算，区别是它是否成为网络条件。显式BPM嵌入的数值归一化和具体层定义在实现前固定。

首要检查编解码往返：单音、双押、四押、混合键型、Hold首尾、同刻结束与重开、跨窗Hold、静音和音频终点。然后检查充分拟合、自由滚动的误结束/缺音，以及生成历史错误后的恢复。原有onset F1只评价Tap/Drag/Flick/HoldStart形成的唯一起点，HoldEnd单独评价结束时间和配对，避免换表示后虚增起点成绩；保留原网格加分、键型联合F1和完整结束统计。

新结构相对旧模型同时改变事件表示、摘要、窗口条件和Hold表示，整体对比不能归因给单一改动。BPM两组内部才是受控单因素对照。当前有BPM组使用全300首、300轮计划；无BPM组尚未启动，不能报告BPM的对照收益。
