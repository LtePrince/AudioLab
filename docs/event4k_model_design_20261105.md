# Event4K：同步事件输入与版本命名（2026-11-05）

按用户最新要求定义 **AudioLab Event4K / AL-Event4K（同步事件AR）**。同一时刻所有轨道事件构成一个token；保留当前音乐时间和整曲音频，移除28维手工摘要，显式BPM做有／无对照。**取消输出分窗与中间END_WINDOW，整曲只监督一次EOS；用户已授权丢弃旧v0.2训练产物，从零启动有BPM的v0.3.0。** 历史设计与运行证据见[E26报告](evaluations/event4k_bpm_20261105.md)，当前训练见[E27报告](evaluations/event4k_fullsong_20261105.md)。发布权重未替换。

## 模型名与版本号

模型名标识基础输入表达结构。旧 `AL-AR4K` 是逐音符及控制token序列；新 `AL-Event4K` 是逐时刻4×5事件矩阵序列。BPM等额外信息不另起模型名。free-x连续坐标不能直接套用4轨矩阵，本次没有登记虚构的EventFreeX权重。

采用 `模型名 v0.C.R`：

- `C` 是条件／输出协议配置编号：1=原分窗无BPM，2=原分窗有BPM；3=整曲单EOS有BPM，4=整曲单EOS无BPM。全部保留时间嵌入，基础4×5输入结构相同，不另起模型名。
- `R` 是该配置下的训练计划编号。按用户最新修订，**一次完整训练计划共用一个版本号，当前300轮全部为v0.3.0**；同一计划中断续跑不升级版本，另一次明确的新训练或微调计划再递增。
- 同一版本可包含多个epoch检查点，以版本、run、epoch/step、参数SHA唯一定位；保存父权重与数据/配置/代码来源。同一检查点身份不能重绑不同参数。打包、改文件名或推理采样变化不新增模型版本，包SHA与参数SHA分开记录。
- `latest`、`best`指向具体检查点，例如`AL-Event4K@0.3.0/e0020`。候选版本可以预留，但在权重实际产生前必须是`weights=null`和未训练状态。

| 模型名 | 版本 | 额外条件 | 当前状态 |
| --- | --- | --- | --- |
| AL-Event4K | v0.1.0 | 原分窗，音乐时间；无显式BPM | 未训练，原实现保存在历史提交 |
| AL-Event4K | v0.2.0（旧每轮标签v0.2.0–v0.2.7仅作历史） | 原分窗，音乐时间＋显式BPM | E26在第9轮终止，用户要求删除旧权重与专属标签；历史来源保留 |
| AL-Event4K | v0.3.0 | 整曲单EOS，音乐时间＋显式BPM | E27-BPM的完整300轮计划；各轮按e0001、e0020等区分 |
| AL-Event4K | v0.4.0（预留） | 整曲单EOS，音乐时间；无显式BPM | 独立对照实现支持，未启动，weights=null |

例如第20轮与第300轮均叫v0.3.0，具体为`v0.3.0/e0020`与`v0.3.0/e0300`。此前日志中的`v0.3.19`映射为`v0.3.0/e0020`，保留历史别名，不重写已有checkpoint的字节或SHA。无BPM组的完整计划同理使用v0.4.0。

旧ID继续作为历史别名，避免破坏报告与release。当前两份同结构的联合训练权重新增唯一映射：`AL-AR4K v0.7.1 = 旧v0.7.0 / E22-A / e20`；`AL-AR4K v0.7.2 = 旧v0.7.0 / E23-A / e300`。原v0.7.0保留为历史结构记录。前次未执行的v0.8.0/v0.9.0及E25提议已被本次设计取代；不复用其ID冒充新的训练。

## 一个时刻，一个事件token

令第i个事件时刻为`t_i`，矩阵`E_i ∈ {0,1}^{4×5}`。行是第1–4轨，列固定为：

```text
[Tap, Drag, Flick, HoldStart, HoldEnd]
```

每格表示该时刻该轨该事件是否发生，是多标签二值矩阵。某轨无事件时整行全0，不需要第六个“空键型”。同刻第1轨Tap、第4轨Hold开始：

```text
        Tap Drag Flick HoldStart HoldEnd
轨1      1   0    0       0        0
轨2      0   0    0       0        0
轨3      0   0    0       0        0
轨4      0   0    0       1        0
```

整个矩阵展平后投影为一个稠密向量。Hold结束作为后续时刻矩阵中的HoldEnd事件表示，不再接DUR token；同刻发生的Hold结束和新音符开始一起编码。事件内没有轨道先后推理顺序，不使用一个巨大“所有组合词表”，也不把双押拆成两个NOTE token。

序列为`BOS, (t_1,E_1), …, (t_N,E_N), EOS`，包含所有起点与Hold结束时刻的并集；只把原数据同一物理时刻的事件合并，不按F1容差或偏好节拍网格吸附。没有事件的时间用时间间隔表示，不枚举音频每一帧作为空事件。BOS和整曲EOS属于控制协议，途中没有窗口控制符。

输入约定为：

```text
x_i = event_projection(flatten(E_i)) + time_embedding(t_i)
      + optional_bpm_embedding(BPM)
```

谱面历史经因果self-attention读取，整曲音频经cross-attention读取。两组都没有手工历史摘要、显式soft起音通道或窗口边界嵌入；音频编码器和解码器全部可训练。音乐时间使用统一物理时钟，BPM不能替代时间嵌入。

## 整曲输出与结束

预测下一事件时间，再在该时间条件下输出4×5事件logits，形成一个事件矩阵。事件头可从20个sigmoid概率与多标签BCE基线开始；不能在全部20格上做单一softmax，也不能对每轨五类强制五选一，否则分别无法表达多押或空轨。采样的是整组多标签事件，不在组内再按轨道推进AR序列。

20个独立Bernoulli是概率分解假设，即使共用hidden也不保证捕获所有同刻相关性。需用整组键型匹配和多押组合分布检查，不能仅凭边缘概率宣称“学会双押”。合法事件组合的掩码/采样及相关性建模细节在实现时单独记录，不预设键型比例或双指上限。

**没有窗口调度、窗口时间mask、窗口结束头或周期性停止标签。** 每个历史前缀在全部剩余有效音频时间候选与整曲EOS之间作联合softmax选择；只限制时间单调递增且处于实际音频范围内。输出单调性限制不缩小cross-attention范围，每一步仍能读取完整音频，包括此前的段落。所有先前事件保留在因果self-attention中，KV缓存整曲只初始化一次，不裁剪、不周期重置。

N个事件有N+1次时间/EOS决策：前N次各预测一个后继事件，最后一次监督EOS；静音只有BOS→EOS。EOS不是下一次输入的事件token，不会出现“生成EOS后再开下一窗”。实际音频耗尽或事件预算耗尽仍可强制停止，但单列为失败，不能统计为学会了EOS。EOS提前产生仍可能缺音，需要自由生成检查；取消窗口本身尚不是质量改善证据。

Hold配对与合法性在编解码/输出检查层维护，不作为手工历史向量喂入网络。保留任意跨度的Hold，以及同轨同刻“旧Hold结束＋新Hold开始”。起音须早于音频末尾，合法Hold尾标签可以等于末尾。无起点的HoldEnd、重复开启未结束Hold、同一格多次事件等必须明确报告；4×5二值矩阵无法无损表示同格重复或需区分身份的重叠Hold，数据审计不得悄悄合并或删除这类样本。

## 对照和验收

E27保留有／无BPM两个独立版本，拟使用同一全300首、相同数据顺序、预算、时钟、整曲协议、采样与评测；共享参数从相同随机张量初始化。BPM投影单独开关，为`log2(BPM/120)`经无偏置线性投影；无BPM组也不额外加入按拍换算的历史摘要。两组导出仍可用相同BPM做格式换算，区别是它是否成为网络条件。旧分窗标签、probe和checkpoint不能直接当作新协议继续训练，schema及输出目录分开；当前没有迁移或重训旧权重。

首要检查编解码往返：单音、双押、四押、混合键型、Hold首尾、同刻结束与重开、长跨度Hold、静音和音频终点；另检查10/20秒处不新增结束决策，完整历史与全曲音频始终可见。然后检查充分拟合、自由滚动的误结束/缺音，以及生成历史错误后的恢复。原有onset F1只评价Tap/Drag/Flick/HoldStart形成的唯一起点，HoldEnd单独评价结束时间和配对，避免换表示后虚增起点成绩；保留原网格加分、键型联合F1和完整结束统计。

Event4K相对旧AL-AR4K同时改变事件表示、摘要、停止协议和Hold表示，整体对比不能归因给单一改动。E27相对E26主要改变输出协议与对应监督，输入表示、参数量不变。两者原本都保留全部谱面历史；本次取消的是分窗的输出限制和周期性结束目标，并非修复一个已证实的历史截断。新协议有BPM组已启动，但没有自然曲质量评价或BPM对照结果，不能报告收益。
