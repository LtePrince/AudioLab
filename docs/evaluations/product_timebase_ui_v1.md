## 三首完整歌曲的同条件对照

使用与首轮工程回归相同的三首开发验证曲。脚本逐项核验音频／权重哈希、未量化候选、随机种子、offset、采样参数、布局编码模式、共享推理配置和运行设备；不一致即失败。原谱 BPM 只作为原有编码时基，不当作听觉审核真值。

六份输出均完成自然 EOS、所有量化候选覆盖和格式／位置／时间硬检查。峰值 RSS 2.344 GiB；PyTorch 记录的 GPU reserved 峰值 0.168 GiB，不含驱动上下文。新增产物 19.60 MiB，结束时磁盘可用 11.83 GiB。

时基会改变 token 时间尺度，因而明显改变布局与键型分布。自动时基的半速、倍速或其他节拍层级尚未校准，不能仅凭完整生成、较少修复或音符数量判断哪份更好。第三首 free-x 自动结果的 42 个 Hold 中有 18 个被截短，原始总持续约 28.39 秒、修复后约 13.00 秒；后续应单独分析持续与音频对应及布局冲突，不设 Hold 数量配额。

可复现命令：

```bash
python -m script.train_models --gpu 1 --worker script.audit_product_tempo -- \

```

运行产物保存在开发工作树 `out/product_tempo_v1/audit.json` 和 `song-{0,1,2}`；原始／最终键型、Hold 秒数、坐标分布、修复和量化误差均在报告中。模型和音频文件不提交 Git。

## 本地浏览器与生命周期

根线程使用实际 Firefox 157，对 `ea963c9`（工作树干净）的本地页面完成：选择并上传真实 102.77 秒 OGG，仅选择玩法后自动生成两模式；并发请求返回 409；结果按钮打开预览新窗口；HTTP 音频返回 206 Range，原生播放、跳转、切换模式正常；实际下载的 JSON 与任务产物相符；取消真实 worker 后释放槽位且无完成产物；损坏 WAV 明确失败并可重试；静音返回 `needs_tempo` 并展开手动设置。

浏览器这一轮双模式推理约 31.61 秒，属于单机单样本观察，不是速度承诺。报告位于主工作树 `out/browser_review/ui-workflow-v2.json`。此前的离线预览、非零 offset、四键型和 Hold 中段跳转证据仍适用。

独立故障注入还覆盖：上传完成后客户端断开不能释放仍活跃的 worker；取消请求之后必须等待子进程实际退出才能重试；写最终完成状态失败时删除完成标记。全套回归 240 项通过后，补充的 WAV→logmel 时轴与对照配置漂移拒绝测试通过，最终入口／管线定向回归 34 项通过。

自动估计明确标为未确认；没有可靠节拍图、学习式 beat 模型或目标播放器兼容认证。人类声学标签、手感与动态演出另行验收。
