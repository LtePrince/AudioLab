# E22-A：暂停 S，A 全音频编码器与分窗解码器联合训练

用户于 2026-11-02 要求暂停 S 技术路线，A 的所有参数参与训练。本轮登记为 **AL-AR4K v0.7.0 / A / E22-A**，从 E16-NW1-FIT100 的分窗 e100 权重开始；不重新初始化已有编谱能力。先在当前 4K 分窗模型执行，free-x 的 A 适配另行登记，不把它算作本轮已训练。S 不再安排训练或优化，历史权重与成绩保留。

## 实际音频编码流程

输入按 22050 Hz 读取并混成单声道；STFT 的窗口为 2048 个采样点、hop 为 512，经过 128 维 Mel 滤波及 dB 转换。严格复用 `AudioGPUprocessor` 的处理约定，并按音频真实时长截取、补齐偶数帧。

```mermaid
flowchart LR
    M["log-Mel：128 × T"] --> C["Conv1d 128→256<br/>4 个膨胀残差卷积块"]
    C --> P["Conv1d，kernel 4 / stride 2<br/>T/2 个 256 维连续 token"]
    P --> E["6 层双向 Transformer<br/>8 头全曲 self-attention + RoPE"]
    E --> N["LayerNorm<br/>全曲音频 memory"]
    N --> X["可训练投影 + 时间编码<br/>谱面解码器 cross-attention"]
    X --> O["当前 10 秒窗口内的时间、键型、位置及结束决策"]
```

这里的 token 是连续向量，不经过词表、码本或音高离散化。每个 token 的时间步长约为 `2×512/22050 = 46.44 ms`；卷积已经融合邻域信息，attention 再融合整曲信息。一个 token 不对应一个真实音符。46.44 ms 是特征时间步长，最终起点还有连续帧内偏移，不是强制吸附该网格。

每个 encoder block 对 `LayerNorm(X)` 做 Q/K/V 投影，八个头各 32 维，对 Q/K 做 RMSNorm 和 RoPE，然后计算 `softmax(QKᵀ/√32)V`。没有因果遮罩或局部窗口，任意音频 token 能读取整曲；注意力输出投影加残差，再经过 `LayerNorm → Linear(256,1024) → GELU → Linear(1024,256)` 的 MLP 与残差。谱面解码器另有因果 self-attention 和整曲 cross-attention。10 秒限制只约束当前输出的时间范围，不截断音频可见性。

## 原先冻结的位置与这次改动

旧音频编码器来自 `checkpoints/timing_v1/decoder/decoder_best.pt` 内的 `encoder.*`，是已经预训练的完整转录特征网络，不是 S 的独立起音网络。后续 A/S 与分窗训练直接读取其离线 feature 缓存，编码器不在优化器内，因此谱面损失不能改善其表示。简单声学探针成功不能证明它足够支持复杂编谱，冻结是否构成主要瓶颈尚未证明。

新入口 `script.train_joint_audio_a` 只缓存固定 DSP 的 float32 Mel 与原始监督标签，所有神经网络特征在每次训练时重新计算。梯度从时间 pointer、帧内偏移、键型/位置与窗口结束损失，经过 memory 投影、全部六层音频 attention、四个卷积块和入口卷积回传。卷积、attention 和解码器都加入优化器。

纯 A 不使用独立起音网络。移除原结构中输入恒为零的 soft-onset 投影，以及不参与 AR 前向的转录输出头，避免把没有梯度的附属参数计入“全部可训练”。保留原特征 float16→float32 数值约定；这两个类型转换可微，不做 `detach`。逐块 activation checkpointing 只重算激活，保持全曲上下文。

## 配方、评价与资源

- 父模型：分窗 A e100，SHA256 `637b80584f2c53cda2235839f0701a3f61fa99f5163a1e3899da5534f73cf87a`。
- 数据：原全部 300 首；每首原整曲、两份固定物理平移裁切、真实静音。保持原标签、10 秒窗口和损失权重。
- 首段 20 轮，共 6000 次更新；解码器 LR `3e-5`，全部编码器 LR `3e-6`。两组均为正学习率，新建 AdamW；编码器恢复原 dropout 训练行为。20 轮是适配首段，不预先称为训练充分或能力上限。
- 训练前使用当前在线编码器重跑 15 首训练曲＋10 首社区开发曲，形成 e0 对照；第 5/10/15 轮检查 Eltaw 与两首缺音曲，第 20 轮重新评测全部 25 首。
- 同时看起点 F1、网格加分、时间＋类型、正常窗口结束、最长有参考起点的缺音区间与 Hold 覆盖，不把单一 F1 上升认定为可用。十首社区曲仍是开发数据，不是盲测。
- 本轮改变编码器可训练性、其 dropout 状态及优化器参数组；属于端到端适配试验。e0/e20 对照不单独证明收益只能来自解冻，若要作严格因果归因仍需同曝光、同优化器的冻结 A 对照。
- 固定 Mel 缓存上限 2 GiB；RSS 上限 6 GiB，可用 RAM/磁盘至少 8 GiB，GPU 分配上限 65%；只保存完整 latest 和最佳拟合权重。原权重只读。
- 启动前检查真实整曲梯度、逐块更新、最大音频/标签长度的资源；推理与训练 checkpoint 必须同时包含新音频编码器与解码器，不能仅导出解码器配旧前端。

## 执行记录

实现与迁移、梯度回传、重算梯度一致性以及 4K/free-x 兼容测试共 **49 项通过**。真实 GPU 测试覆盖 Eltaw、最长音频 Drop It、最长谱面「祈 -我ら神祖と共に歩む者なり-」，三组都验证了 **279 个参数张量全部获得有限梯度，且 optimizer.step 后全部变化**；六层音频 attention、四个卷积块、入口/降采样/归一化与解码器均通过逐组检查。探针更新全部丢弃，正式运行重新载入原父权重。

模型总参数 **13,371,139**，其中完整音频特征网络 **6,679,424**、分窗谱面网络 **6,691,715**，全部可训练。三首真实训练步骤的 RSS 峰值约 1.915 GiB、GPU 已分配峰值约 0.371 GiB（保留峰值 0.631 GiB）；这不是全部歌曲或服务端资源上限认证。全部固定 Mel 缓存 **1.438 GiB**，准备后磁盘剩余约 **27.03 GiB**。

后台任务通过独立 POSIX 会话启动，首个阶段为在线编码器 **e0 的 25 首基线评测**，随后自动进行 20 轮联合训练；启动快照为 0 次正式更新，不把梯度探针算成训练进度。实时阶段和轮次读取 `out/joint_audio_a_20261102/training.json` 并核对进程，失败信息记录在 `failure.json`。启动证据见 [状态与验证](assets/joint_audio_a_20261102/startup.json)、[完整参数/源码配置](assets/joint_audio_a_20261102/config.json)、[逐参数真实梯度](assets/joint_audio_a_20261102/gradient_probe.json)。当前没有新的训练后质量结论。
