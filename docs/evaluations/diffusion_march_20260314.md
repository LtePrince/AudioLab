# 三月 diffusion v2：精确复现与同一 benchmark

使用 [diffusion-20260314 Release](https://github.com/LtePrince/AudioLab/releases/tag/diffusion-20260314) 的三月权重和同期 `20edd4d35b584dccd6608dafa92d7028bf41d80f` 代码，成功复现用户上传的 Eltaw v2：**531 个音符的起止时间、四键位置、键型逐项完全一致，463 个唯一起点完全一致**。这里比较的是完整音符事件，不是仅比较数量或 F1；封面及谱包元数据不在一致性断言内。

三首既有开发曲的参考起点 F1@50ms 宏平均为 **0.7673**，当前 AR global/seed42 采样为 **0.6037**。旧 diffusion 在这些曲目上优于这一 AR 采样配置；同一 AR 的贪心模式也存在全 Tap 却获得较高起点 F1 的退化，不能泛化为架构优劣结论。纯静音通过，但四个正例钢琴探针均失败，不能据此称整个模型已经满足产品要求。训练差异、AR 缺口和八月固定长度对照见[归因审计](diffusion_ar_attribution_20261023.md)。

## 历史行为与执行方式

新增 `script/replay_march_diffusion.py`：从固定 Git 提交临时导出 `src/`，在独立 Python 进程中加载，拒绝混入已经导入的当前 `src`；三套模型 strict 加载，逐输入校验哈希，模型和采样使用未经修改的三月实现。当前资源检查以独立模块加载，不替换历史音频或模型代码。生成后临时源码自动清理，输出再交给现行 benchmark 评分器。

固定 seed=42、CFG=3、DDIM=50、eta=0、max_frame=4096、sr=22050、hop=512、mel=128。三月代码将音频 mel 固定到 4096 帧，谱面也固定为 4096 帧，保留后来修正的 2 倍时间轴问题；转换器按历史默认 `from_logits=False`（二值阈值 0.5）解释输出。本轮不将这些历史行为悄悄换成当前原生长度推理或阈值 0，以免改变被复现对象。

这些设置用于确认历史模型表现。后续如修正时基，应保持训练和推理一致并另立实验记录；当前结果不足以证明保留旧时间错误有利，也不能直接把三月权重装入当前产品推理路径宣称效果相同。

本地请求在 `out/diffusion_march_20260314/request.json`。重新运行前复制请求并将 `output` 改为新的空目录，再执行：

```bash
.venv/bin/python -u script/replay_march_diffusion.py \
  --request /path/to/copied-request.json --gpu 1
```

本地预测、日志与资源记录在 `out/diffusion_march_20260314/model/`；同级 `inputs.json`、`report.json` 保留五组完整评分输入与结果，`upload_comparison.json` 保留精确匹配断言。[机器可读摘要](diffusion_march_20260314.json)记录权重、代码、协议、输出指纹和逐例分数。

23 项现有适配器/评分器测试通过；历史执行器本身完成了三套真实权重加载、8 例实际推理和 Eltaw 全音符精确匹配验证。8 次推理共 13.95 秒，RSS 快照 1.505 GiB，torch 显存峰 allocated/reserved 为 1.050/1.373 GiB（包含原始 checkpoint 加载），可用磁盘 16.44 GiB。运行环境为 Python 3.13.13、PyTorch 2.10.0+cu128、RTX 3090；这不是整套产品服务的资源保证。

三月权重保留在 `out/diffusion_march_20260314/assets/weights/`，下载 ZIP 在哈希/推理验证后清理。没有新增 worktree、训练任务或产品默认模型切换。
