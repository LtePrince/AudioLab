# 三月 diffusion、八月 diffusion 与当前 AR 的归因审计

三月模型在既有三曲的采样结果上领先已经复现；目前证据不足以把领先归结为 diffusion 天生优于 AR。比较同时改变了训练预算、编码器、数据处理与解码方式。当前 AR 的直接问题是音频条件利用弱、自由生成退化和训练目标不足；它已经能看全局音频，不能再用“没有全局 cross-attention / 没喂 skeleton”解释。

本轮只做代码/训练记录审计和八月固定长度推理对照，没有重新训练或切换产品模型。这里的“当前 AR”特指 `4k-scratch/global` 的 10 轮从零训练实验，不是用户曾安装的 `full300_history` 权重。完整数值与来源哈希见[机器可读记录](diffusion_ar_attribution_20261023.json)。

## 比较对象与训练充分程度

| 对象 | 生成主体参数 | 所测 checkpoint 的训练记录 | 三曲起点 F1@50ms |
| --- | ---: | --- | ---: |
| 三月 DiT | 64,495,120 | epoch 2000 / step 74000，冻结 VAE/Wave | 0.7673 |
| 八月大 DiT | 64,495,120 | best epoch 293 / step 9669；本轮 epoch 393 停止 | 0.4611 |
| AR global，top-p=.95 | 6,527,745 | 随机初始化 decoder，10 轮 / 3300 更新，冻结声学编码器 | 0.6037 |
| 同一 AR，贪心 | 同上 | 同一权重 | 0.6960，但三曲全部退化为 Tap |

参数量比较只计 DiT / AR decoder 主体，不包含各自不同的前端。AR 的 3300 更新为 3000 次音乐、300 次静音；音乐 token CE 从第 1 轮 2.4952 降至第 9/10 轮 1.4266/1.4140，不能称已充分收敛。不同任务的 epoch、step 和 loss 不能直接换算计算量或优劣；八月计数是本轮记录，不能断言模型全部生命周期只有这些更新。

三月与八月大 DiT 参数量相同，容量不能解释二者差距。三月与 AR 则容量和预算都不匹配：当前结果没有完成同等预算下的架构优劣实验。

AR 明确用全部 300 首训练。三月 Release 记录 300 样本，但原始逐曲清单尚未复核。当前 270/30 列表将 Eltaw 分到 train、另两曲分到 val；没有历史清单哈希把它们绑定到八月 checkpoint，因此八月的逐曲训练成员身份仍未确证。共享 benchmark 的 `seen_training` 标签来自 AR，不能据此断言 diffusion 见过同样的歌曲。

## 三月为什么更好：已定位的差异与尚不能归因的部分

三月 Eltaw 与上传 v2 的 531 个音符逐项相同，排除了拿错历史模型的问题。三月 P/R@50ms=0.9050/0.5977，只有 44 个未匹配输出起点；八月为 0.5959/0.4608、219 个未匹配输出起点；当前 AR 采样为 0.4303/0.7261、674 个未匹配输出起点。因此在这首歌上，三月的优势具体表现为取音更准、额外起点更少，并非单纯“音符更多”。

但三月旧代码将 mel 截到 4096 帧，约 **95.1 秒音频**，谱面轴却覆盖约 190.2 秒。Eltaw 实长约 135.55 秒；生成谱在 95.1 秒以后仍有 116 个唯一起点。该段没有对应的直接音频帧输入（STFT 边缘只带来很短的邻域），只能依赖前段条件与学到的谱面规律。训练曲记忆、重复段落推断可能贡献了好成绩，不能把它全部解释为更强的逐时刻音频理解；这不是已证明的记忆机制。三月也漏掉了全部三音/弱音/重复音钢琴探针。

八月同时更换了 VAE/Wave 权重、音频与谱面时间对齐、Wave 联合训练、dropout、验证选模和推理长度/二值输出解释。三月从 logits 以 0.5 为阈值，当前以 0 为阈值；这也是未隔离的差异，不应把它直接变成提高阈值的产品修复。VAE scale 的 1.0→1.004 本身幅度很小，不能单独拿来解释巨大下降。

八月按验证集去噪 MSE 选择 best，这不是按成谱质量选模。所测 epoch 293 的条件去噪收益为 **+3.99%**；最终 epoch 393 为 −0.66%，不能把末轮负值错误归到所测 best。现有记录说明“噪声损失最佳”和“生成谱最好”还没有建立对应关系，不能证明联合训练本身导致退化。

本轮新增单因素对照：八月同一组权重、代码、音频、seed=42、CFG=3、DDIM=50、eta=0、二值阈值不变，只将原生长度改为固定 4096 谱面帧。

| 开发曲 | 八月原生长度 | 八月固定长度 | 三月历史实现 |
| --- | ---: | ---: | ---: |
| SURREALISM | 0.3631 | 0.3866 | 0.8000 |
| ABYSS MOTION | 0.5004 | 0.5286 | 0.7818 |
| Eltaw | 0.5197 | 0.5127 | 0.7199 |
| 宏平均 | 0.4611 | 0.4760 | 0.7673 |

在这三曲和单种子下，固定长度只增加 0.0149，解释不了主要差距。该对照没有重现三月的旧音频时轴或阈值，不能进一步断言所有推理差异都已排除。输出位于 `out/diffusion_attribution_20261023/august_fixed/`，8 例全部完成推理；RSS 约 1.55 GiB、torch 显存峰约 0.59 GiB、剩余磁盘约 17.1 GiB。

## 当前 AR 的具体缺口

1. **条件进入了网络，但没有形成足够强的音频依赖。** 输入是连续 256 维音频帧，不是离散音频词表；软起音概率和偏移通过投影加到 memory，弱起音未在此阈值过滤。global 版本的每个 query 能看全部有效音频帧。Eltaw 在真实历史条件下，清零声学特征仅使平均 NLL 从 1.64057 增至 1.65739 bits/token（约 1.03%）；清零软起音为 1.64059。其他两曲声学清零增幅约 1.2%–1.7%。这支持“在真实前缀下增量条件收益弱”，但两路互补、零特征分布异常都可能影响结论，不能等同于真实静音测试或断言完全不看音频。见 `chart_decoder.py:prepare_memory`、`soft_onset.py:forward_loss`。
2. **时间定位、排布与停止共用一个自回归序列。** DTB/DTT 自己预测时间增量，再与键型×位置、Hold 时长、EOS 一起从同一词表逐步生成。累计时钟由预测 DT 推进；一次时间选择错误会改变之后的 query 时间和历史，已输出部分不能回改。当前没有直接监督“这一音对应哪一个音频起点”的独立对齐目标。全局 attention 提供了访问能力，不会自动保证正确定位。
3. **训练历史与实际生成历史不一致。** 训练用真值 token、真值时钟和真值前缀特征；自由生成用自己的结果。15% token embedding dropout 没有模拟错误时钟或错误历史的连续影响。主要目标是逐 token CE，训练损失没有直接针对自由生成时的起点、停止和密度错误给出纠正信号；这为误差累积提供了条件，不能仅凭它解释全部实测下降。现有评测虽能测出这些问题，尚未将其解决。
4. **模式特征已加入，但段落组织没有得到充分训练。** 28 维历史描述最近位置、间隔、重复、交互、单调方向等；因果 self-attention 也能访问完整过去。当前 checkpoint 未开启关系辅助头，也没有把音乐重复段落与谱面重复/模进建立专门训练目标。添加历史描述不等于学会短纵、楼梯和段落呼应。即使开启邻接关系头，也不等同于完成段落学习。
5. **概率输出与质量指标暴露退化。** Eltaw 采样生成 1321 音符，F1=0.5403，并在 127.31 秒结束；贪心生成 1356 音符、全部 Tap，F1 却达 0.7395，甚至高于三月 0.7199。贪心基本落在重复半拍起点上；F1 不评价键型、轨道与音乐动机，网格奖励也不能替代这些要求。不能用提高网格分或换 greedy 宣称修好。
6. **短片段训练存在潜在捷径。** 静音训练为 5/13/26/41 秒，音乐主要为整曲；静音 BOS→EOS 以单独一次优化更新训练，音乐 loss 则按整曲 token 平均。长度和正负标签相关，单 EOS 的权重也可能偏大。这是有代码依据、尚未单因素验证的假设。当前 global 对 10 秒三音输出空谱，前端能识别三次起音，第二阶段仍未通过基础对应检查。

其中第 2 项的不可回改和因果输出是当前生成方式的结构性限制；第 1、3–6 项主要是训练/表示/目标与解码校准问题。diffusion 每次去噪可同时更新整段谱面，对协调前后布局提供了另一种机制，但本轮没有证明该机制单独带来多少收益。没有证据表明 cross-attention 的算法本身不适用于此任务。

## 下一步应如何验证和修正

- 保留三月精确复现为可用效果参照；三月→八月逐项核对 VAE 重建质量、输出解释、时轴及训练/选模。固定长度已做；其余因素不在本轮伪装成已验证原因。时轴变化涉及训练分布，不能只在旧权重推理端改时间后就下结论。
- AR 先做同长度有声/静音片段和联合 token 归一化训练，消除明显混杂；增加对应音频/错配音频的成对诊断，既看真实历史 loss，也看自由生成的音符是否随音频移动。冻结已有探针，禁止把评测文件直接当训练样本。
- 保持全局音频可见，尝试由模型学习起点选择/时间对齐，再在相应起点条件下生成和弦、键型、位置和时长；可共用 Transformer 联合训练，不必强制改成两个互不关联的模型。弱起音继续作为软证据，不固定键型比例，不按网格硬排布，不默认限制为双指。
- 通过基础音频对应后，检查持续训练至收敛的增益，再在相同数据和预算下比较模型容量。同时评估自由生成、重复/模进与模式持续性；只降低 teacher-forced CE、提高起点 F1 或网格奖励均不足以选模。

本轮完成推理与数据一致性核验，不涉及训练代码变更。以上后续实验尚未执行，不将方案写成已经修复。
