# 本地整谱闭环工程验证

日期：2026-10-17。代码：`f9c49c9` 首轮分块实验，`cdb881c` 保留整曲布局编码后的默认入口。开发验证集 30 首按曲长选择最短、中位、最长三首，复用 `timing_v1` 权重，seed=42。这是可复现工程样本，不是冻结产品测试集或人工可玩率。

## 默认全曲布局编码

RTX 3090 GPU 1，CPU 两线程，串行生成 4K 和 free-x。提供的原谱 BPM 仅作为编码时基，未当作音乐 BPM 真值。完整结果位于运行目录 `out/product_smoke_full_v1/audit.json`，每首目录包含全部产物及哈希。

| 144.13 秒 | 38.05 秒 | 993 | 993 |

峰值进程 RSS 约 2.135 GiB，PyTorch GPU reserved 峰值约 0.168 GiB；后者不包含驱动及上下文全部开销。生成期间保留约 11.87 GiB 磁盘空闲。每首每模式自然生成 EOS，量化候选完整覆盖；格式、音频时间、Hold 尾部、位置和视觉距离检查通过。资源预算先估算再执行，超限明确失败，不自动切换布局编码语义。

## 分块对照为何保留为实验

同一首 102.77 秒歌曲、同一 547 个候选起点、同权重及 seed，布局编码从整曲注意力变成 1024+128 mel 窗口后：4K 从 735 变成 680 音符，free-x 从 783 变成 703；free-x Tap 从 633 变成 349、Drag 从 93 变成 325。两者均完整保留候选时刻，说明起点覆盖不能证明动作分布无回归。

这些数量不是键型配额或质量评分，不能单凭它们判断哪份更好玩。改变已训练模型条件分布的效果尚未校准，因此默认保留历史整曲布局编码，分块需显式选择。共享音频候选的分块配置另行记录，不与布局编码混为一个开关。对照保存在 `out/product_smoke_v1/audit.json`。

## 界面与失败行为

独立 Firefox 157 浏览器验证覆盖播放、暂停、跳转、重置、倍速、自然播放到结尾、两模式切换、四键型视觉、实际 Hold 中段跳转、预览与导出时间／位置一致，无外部网络依赖。合成样例使用 offset=0.25 秒、Hold=0.75–2.25 秒；另检查三首真实分块产物和默认全曲首曲。浏览器证据由主会话保存在 `AudioLab/out/browser_review/`。

空候选、token 预算耗尽、资源不足、取消、第二路线失败和重复目录均不能获得完成 manifest。审查发现“所有候选已覆盖但末和弦被预算截断”的边界后，产品入口已独立要求自然 EOS，旧模型调用默认行为保持兼容。

这份验证没有审核独立声学标签、目标游戏判定或真人完整试玩。速度仅为三个样本的观察值，不是已获批 P95 承诺；无轨仍为静态单线。
