# 模型 benchmark v1：把现有要求变成固定测试

2026-10-22。用于后续模型对照；定轨 4K、静态 free-x 分开出表。当前协议、手算样例和小音频标签固定在 `benchmarks/v1/`，入口为 `python -m script.benchmark_models`。**评分代码不会修改生成、阈值、采样、训练损失或音符。**

## 用户确认的节奏评分

每拍 32 ticks，关注拍内 **0、4、8、16、24、32** 的匹配；32 是下一拍的 0，不重复计数。**匹配加分，不要求固定顺序、每段数量或命中比例，不作为解码约束。** 12、20、28、三连音、切分、自由速度等不命中这个 profile 时，只是不获得这项奖励，不判成错误。其他 profile 应另起版本对照，不在看完结果后改规则。

将音频秒 `t` 映射为 `q = (t - 拍零点秒数) × BPM / 60 × 32`。计算 `q mod 32` 到上述位置的最短环形距离 `d`。当前工程计分为 `bonus = max(0, 1 - d / 1 tick)`：精确匹配加 1，偏离半 tick 加 0.5，一 tick 以外加 0；这个宽度是 **benchmark v1 参数**，不是 Phira 判定窗口或产品质量承诺。

按完整谱和默认每 **8 拍统计窗** 报告：唯一起点数、匹配数、各 tick 命中数、奖励总和／起点数、连续命中长度、常见起点间隔及其次数。统计窗不冒充识别到的音乐段落；有人工段落时通过 `segments` 提供范围。每段同时显示参考起点数、输出起点数、全部音符数和四键型数量。

同刻多押在 skeleton 中只算一次；键型／多押另外统计。空谱的平均奖励为 `null`，不能拿满分。展示原始匹配数量，但跨曲比较用平均奖励和分母，不能靠增发音符刷总分。**这一项独立展示，不能抵消静音误报、漏掉弱音或提前结束。** 规则只描述所选节奏位置的匹配，不意味着越高就越符合这首音乐。

BPM／拍零点必须固定来源：构造真值、人工拍点、参考谱、自动估计分开记录。禁止针对预测事后找最优相位／速度。当前自然曲使用参考谱时基，未经独立拍点审核，只作描述；不把 token 已量化当作听准音乐。无时基时写 unavailable，不能临时填 120。v1 只接受常速时基；变速曲需按已审核的常速片段分段，尚不支持整曲 tempo map。

## 测试矩阵与判读

| 编号 | 要求／测试 | 直接输出 | 验收或解释 |
| --- | --- | --- | --- |
| A1 | 10 秒三个独立钢琴音，其他时间无声 | P/R/F1 @25/50/100ms，匹配误差、漏报与误报 | 构造样例基础检查：3 个唯一起点在 ±50ms 一对一命中，无额外起点；四键型／同刻押数不限 |
| A2 | 中间钢琴音振幅为其原值 3% | 弱音召回与整体 P/R/F1 分开 | 同 A1；不能提高阈值删掉弱音来过关，不能把弱拍与低振幅混为一谈 |
| A3 | 同音重复三次；1/24/29 秒跨分块样例 | 每例漏报、误报、时间误差 | 重复音不能合并，不能在分块边界丢音；固定 5 个小样例的音频 SHA 与构造时间 |
| A4 | 真正的零波形、样例内已知静音区间 | 静音误出音数；与 A1–A3 成对检查 | 误出音为 0；不以清零中间特征替代零波形；全程空谱不能通过正样例 |
| S1 | 逐段节奏匹配 | 上述奖励、tick 分布、IOI 分布、每段密度 | **加分项，无固定排布／数量／及格线** |
| S2 | 自然曲骨架对应与弱事件覆盖 | 唯一起点 P/R/F1、弱音召回、误报/分钟、未匹配率 | 声学人工标注与谱面取音分开；参考谱是一个有效编排，不是唯一答案 |
| G1 | 整曲生成、起点与提前结束 | 首个参考／输出时间，参考末四分之一事件召回，空的正样例段，EOS 时钟／越过曲尾秒数 | “正常发 EOS”不等于覆盖整曲；不要求曲尾静音必须出音 |
| K1 | 短纵、长纵、连续交互、楼梯 | 同轨连续 2–3／≥4 个起点链、最长链，AAAA／ABAB／单调四点窗口数 | v1 的短／长按链长度描述；连续四个单点窗口才归类，多押打断，不能跳过多押凑模式 |
| K2 | 模式与上下文对应 | 可标注 `pattern_targets` 的时间段、预期类别及命中窗口数 | 只有明确指定／标注的段落才评价模式命中；自然曲出现次数不是质量目标；模型的模式续写专项集尚待补齐 |
| K3 | Tap／Drag／Hold／Flick、前半段 Tap 偏多 | 每段四键型数量；指定类别／持续的人工核对 | 保留四种键型接口；**无 Hold 配额，无要求每首都含四类**；声学持续不直接当 Hold 真值 |
| K4 | 无缝 Hold、重叠与空间关系 | 同位置 Hold 结束与后续 Hold 起点接触／重叠数、具体例子 | 接触不自动判错，先定位源输出与渲染／修复；free-x 此处同位置指同 bin，非触屏碰撞判定 |
| K5 | 多指与 free-x 坐标 | 押数分布、归一化坐标边界；现有模式几何工具可补充残差／位置变化 | 无默认双指上限；bin+残差需正确反归一化；目标 Phira 判定与真机操作另验 |
| P1 | 原始／修复／最终谱、整包、资源 | 每层分别评分，修复日志、导出校验、耗时、峰值内存／显存 | 不把修复收益算成模型能力；现有产品／导出检查复用，本文评分器不代替实际生成与真机验收 |

A1–A4 是先解决明确失败的基础工程检查；适用于这些受控音频，**不要求自然音乐每个声音都成音符**。自然曲候选目标仍沿用 README 的待校准指标，不把这次构造检查门槛升级为对外准确率承诺。构造样例不能替代独立自然曲测试。

唯一事件匹配复用 `src/audio_understanding/evaluation.py`：微秒去重、一对一最大匹配数，再最小化总时间误差。±100ms 配对后的误差与未匹配比例同时看；区间外输出仍计误报，未审核区间不当负标签。禁止把静音 F1=1 混入正样例宏平均，禁止把失败／缺失任务悄悄丢掉。

## 固定数据、采样和缺项

1. **构造开发集**：`benchmarks/v1/probes.json` 固定三音、弱音、重复音、跨块、纯静音 5 例。使用已编辑钢琴采样，不是独立自然录音测试。采样来源及许可沿用 `script/probe_isolated_onsets.py`（Alexander Holm，Salamander，CC BY 3.0）。训练中用过相似静音，也应明确记录。
2. **自然曲开发对照**：Surrealism、Abyss、Eltaw；4K／free-x 的参考与模型哈希分别保留。全部 300 首已训练，旧 val 名称不恢复为独立测试。自动估计 BPM 与参考谱 BPM 也不混比。
3. **待补的独立集合**：新歌曲按音频来源隔离，人工审核起音／弱音／静音／拍点；后续固定段落与玩法模式标注及 Phira 手机／平板盲测。听看／触摸评价不由程序填写，缺失就写缺失。
4. **采样配置**：greedy 单独报告；随机采样固定 seeds 42/43/44、temperature=1、top_p=0.95，逐 seed 看失败率与波动，再按歌曲汇总。当前已有结果仅 seed 42，不能宣称采样稳定性通过。oracle／zero 条件是独立消融，默认导入器仅评分 predicted 条件。
5. **不掩盖负例**：输出 status=failed 与预测缺失都留在应评数。JSON 的 `contract_status` 表示已实现的基础检查，`coverage_status` 表示预定义案例是否有输出；它们都不表示完整产品质量通过。通用输入应包含全部计划测试，不可只提交成功曲。

每个结果保存协议、案例、预测、源产物和评分代码 SHA。案例或配置改变后，不能直接沿用旧版本基线；`--baseline` 会拒绝协议、案例、采样／选择配置不一致的对照。模型 checkpoint 可以替换。每组按歌曲计权：同一音源同类标签需先合成一个有 coverage 的 case，不重复累计多个重叠难度／片段。

## 直接运行

在 AudioLab 根目录、已安装依赖的环境里：

```bash
# 仓库自带的手写正确答案，只验证评分入口；不是模型成绩，不需要音频／GPU
python -m script.benchmark_models \
  --input benchmarks/v1/example.json --output out/benchmark-example

# 开发机：重放本轮已有模型产物，不重新训练／推理，不加载模型权重
python -m script.benchmark_models \
  --audit-root out/onset_attention_20261022 \
  --output out/benchmark_v1

# 后续模型：导出相同案例的新预测，直接评分并与冻结报告对照
python -m script.benchmark_models \
  --input out/new_model_predictions.json --baseline out/benchmark_v1/report.json \
  --output out/benchmark_next
```

输出为 `report.md`、完整分段与失败项 `report.json`、可迁移的 `inputs.json`。开发机的历史产物与 cache 不随 Git 克隆；复制 `inputs.json` 后可在另一台 PC 用 `--input` 重放，无需复制训练缓存。新模型的推理结果需要另行生成；本入口不伪装执行了模型推理。`--fail-on-contract` 供 CI 检查已定义案例的基础失败／缺失，不能用它认证音乐性或完整采样矩阵。

输入结构见 `benchmarks/v1/example.json`。`runs[]` 含 `id`、`metadata`、`cases`、`predictions`。每例标注音频秒、来源、数据划分、coverage、参考事件和可选拍钟；`predictions[case_id]` 提供 status 与 `onsets_seconds`。布局另给 `notes[{time_seconds,end_seconds,type,position,screen_x}]`；onsets 必须与 notes 的唯一起点一致。`position` 是 4K 轨号／free-x bin，`screen_x` 是已反归一化的屏幕比例。原始和最终谱各建一组，`metadata.stage` 区分。弱音用 `weak_events_seconds`；段落用 `segments[{id,start,end}]`；指定模式用 `pattern_targets[{start,end,label}]`，类别为 AAAA／ABAB／monotonic_run。节奏评分只读输入，不吸附事件。

本轮现有产物基线见 [固定对照结果](evaluations/benchmark_v1_20261022.md)。后续先检查三音／弱音／静音回归，再看段落节奏奖励、自然曲对应与模式证据；不继续用 loss 或单一 F1 代替这些检查。
