# 无轨 Phigros 谱面生成 — 方案设计（v1）

> 目标：从 4k 定轨升级到真 Phigros 风格——连续 positionX、多判定线、
> 线的运动/旋转演出。本方案以 300 首原始官谱的实测数据为依据。

## 0. 数据勘探（60 首原始官谱, 54,597 音符）

| 事实 | 数值 | 设计含义 |
|---|---|---|
| 判定点屏幕坐标可精确还原 | x∈[0.15,0.85] (p1-p99)，出界仅 0.03% | **玩法层可以从官谱无损挖掘**（在击打时刻求值线变换） |
| 带音符判定线 | 中位 11 条/首，最多 24 | 线是演出的"画笔"，不是玩法必需 |
| 击打时刻线在移动/旋转 | 32.6% / 38.2% | 演出很实质，但-- |
| 击打时刻线≈水平 | 65.8%（>5° 倾斜仅 15.2%） | --玩法核心仍是"沿 x 的落点序列" |
| positionX | 连续（0.01 精度下 1390 个取值），[-6.2, 6.1] | 必须离散化或回归，不能扩轨道数 |
| 判定点 y | p50=0.20，p99=0.85 | 大多在底部窄带，高潮段会上浮 |

## 1. 核心解耦：玩法层 vs 演出层

```
玩法谱 (gameplay chart)          演出 (presentation)
──────────────────────           ─────────────────────────────
每音符: (tick, 键型,             把玩法谱"排演"出来:
        判定点屏幕坐标 hit_x     - 音符→判定线的分配
        [, hit_y, 进场角 θ])     - 每条线的 move/rotate/speed/
                                   disappear 事件曲线
可玩性约束在这一层                 同一玩法谱有无数种合法演出
(手速/间距/重叠)                  = 风格问题,欠定,生成式
```

依据：判定点还原实验证明玩法层是**良定义、可挖掘**的监督目标；
演出层自由度巨大（24 条线实现同一落点序列），300 首学不动端到端，
但**机械合成器**可以保证合法性（分段线性事件正是官谱格式的原生表达）。

## 2. 三阶段路线（每步独立可验证、可玩）

### P1 — 自由横坐标（单静态线）

- **数据**：挖掘管线把 300 首官谱转成玩法谱（击打时刻求值线变换 →
  (tick, type, hit_x)），y 固定、θ=0。不再用 4k 量化版本训练。
- **模型**：AR decoder 词表扩展——每个 NOTE 后接位置对
  `POSC_0..15` + `POSF_0..15`（粗细两级 = 256 bins ≈ 0.35% 屏宽 ≈ 7px），
  词表 +32。和弦内排序从"轨道升序"改为"位置 bin 升序"。
- **约束**（语法 mask 扩展）：同和弦最小水平间距；相邻音符手移速度
  上限 |Δx|/Δt；Hold 期间同侧不排密集出击。
- **评估**：onset F1（不变）+ 位置分布 Wasserstein 距离 + 人体工学
  违规率 + 可视化（plot_chart 扩展连续 x，改动极小）。
- 产物直接可玩：单水平线经典下落，官谱格式 writer 现成。

### P2 — 程序化演出合成器

- 输入 P1 玩法谱 + 音频结构（能量/novelty 分段）。
- **机械求解**：给定 (hit_x, hit_y, θ, t)，构造一条线的 move/rotate
  事件使其在 t 时刻恰好以角度 θ 经过判定点——分段线性插值封闭可解；
  音符分组共享线（官谱惯例：一组音符一条线，线数不设硬限）。
- **模式库**（手写、参数化、按段落调度）：静线 / 缓漂 / 下拍旋转 /
  分裂双线 / 副歌上浮（对应勘探中 y 上浮现象）……seed 可复现。
- 永远输出合法官谱（4k_verify 扩展为 freeform_verify：事件覆盖、
  出界检查、opacity 合法）。风格有限但**保底可玩、可发布**。

### P3 — 学习式演出（在 P1+P2 之上）

- 挖掘每音符的**进场属性**：击打时线角 θ（勘探已算）、线速度、
  线归属分组——全部可从官谱精确反算，形成监督数据。
- 小型序列模型预测 (θ, 分组, 模式标签)，仍由 P2 合成器落地
  ——学的是"排演决策"，不是原始事件曲线，数据效率高一个量级。
- 备选：按音乐结构检索真谱演出模板迁移。

### P4（研究向，暂缓）
端到端事件曲线生成（diffusion over piecewise-linear curves）。

## 3. 复用资产清单

| 资产 | 无轨复用方式 |
|---|---|
| 转录编码器 / AR decoder 计划 | 原样；词表 +32 位置 token |
| chart_tokenizer + GrammarState | 扩展 POS 对与间距规则 |
| 官谱 writer / 4k_verify | writer 现成；verify 换约束集 |
| plot_chart | 轨道带 → 连续 x 轴，半天 |
| 30 首 F1 评估 | onset 部分不变，加位置指标 |
| 4k 定轨产品线 | 保留为 POS 恰取 4 个 bin 的特例 |

## 4. 风险与对策

1. **演出学习数据薄** → P2 程序化打底，P3 只学低维决策；
2. **人体工学模型**无现成标准 → 从速度/间距双约束起步，靠试玩迭代阈值；
3. **Hold 在移动线上**（判定点随线漂移）→ P2 先限制 Hold 只排静线段，
   P3 再放开（勘探待补：移动线上 Hold 占比）；
4. 挖掘的 hit_y 高潮段上浮 → P1 忽略 y 是有意简化，P2 用段落模式补偿。

## 5. 首个落地任务（CPU 即可）

`script/mine_gameplay.py`：官谱 → 玩法谱 JSONL
（tick/type/hit_x/hit_y/θ/线id/dur），全 300 首 + 分布报告
——它同时是 P1 的训练数据源和 P3 的监督源。
