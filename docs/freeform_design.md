# 无轨 Phigros 谱面生成 — 方案设计（v1）

> 目标：从 4k 定轨升级到真 Phigros 风格——连续 positionX、多判定线、
> 线的运动/旋转演出。本方案以 300 首原始官谱的实测数据为依据。

## 0. 数据勘探（60 首原始官谱, 54,597 音符）

| 事实 | 数值 | 设计含义 |
|---|---|---|
| 判定点屏幕坐标可精确还原 | x∈[0.15,0.85] (p1-p99)，出界仅 0.03% | **玩法层可以从官谱无损挖掘**（在击打时刻求值线变换） |
| 带音符判定线 | 中位 11 条/首，最多 24 | 线是演出的"画笔"，不是玩法必需 |
| 击打时刻线在移动/旋转 | 32.6% / 38.2% | 演出很实质，但-- |
| 击打时刻线≈水平 | 65.8%（>5° 倾斜仅 15.2%） | --玩法核心仍是"沿 x 的落点序列" |
| positionX | 连续（0.01 精度下 1390 个取值），[-6.2, 6.1] | 必须离散化或回归，不能扩轨道数 |
| 判定点 y | p50=0.20，p99=0.85 | 大多在底部窄带，高潮段会上浮 |

## 1. 核心解耦：玩法层 vs 演出层

```
玩法谱 (gameplay chart)          演出 (presentation)
──────────────────────           ─────────────────────────────
每音符: (tick, 键型,             把玩法谱"排演"出来:
        判定点屏幕坐标 hit_x     - 音符→判定线的分配
        [, hit_y, 进场角 θ])     - 每条线的 move/rotate/speed/
                                   disappear 事件曲线
可玩性约束在这一层                 同一玩法谱有无数种合法演出
(手速/间距/重叠)                  = 风格问题,欠定,生成式
```

依据：判定点还原实验证明玩法层是**良定义、可挖掘**的监督目标；
演出层自由度巨大（24 条线实现同一落点序列），300 首学不动端到端，
但**机械合成器**可以保证合法性（分段线性事件正是官谱格式的原生表达）。

## 2. 三阶段路线（每步独立可验证、可玩）

### P1 — 自由横坐标（单静态线）

- **数据**：挖掘管线把 300 首官谱转成玩法谱（击打时刻求值线变换 →
  (tick, type, hit_x)），y 固定、θ=0。不再用 4k 量化版本训练。
- **模型**：NOTE token 直接融合位置——`NOTE_{4键型}×{64位置bin}`
  （256 个 token，**1 token/音符**，序列长度与 4k 版持平）。
  两个关键补丁使其在 300 首数据下可行：
  1. **因子化 embedding**：`E[NOTE_t_p] = E_type[t] + E_pos[p]`——参数
     按键型/位置因子共享（等价于拆分方案的样本效率），输出仍是
     256 类满 softmax（联合分布满秩）；
  2. **连续偏移回归头**：在 NOTE token 隐状态上回归 bin 内亚像素偏移
     （anchor+offset 套路）——不占序列、不进自回归，位置精度无上限。
  和弦内排序从"轨道升序"改为"位置 bin 升序"。
  （曾考虑 NOTE+POSC+POSF 三 token 拆分：联合分布同样可表达，但序列
  ×2、解码错误面 ×2，被上述方案取代。）
- **约束**（语法 mask 扩展）：同和弦最小水平间距；相邻音符手移速度
  上限 |Δx|/Δt；Hold 期间同侧不排密集出击。
- **评估**：onset F1（不变）+ 位置分布 Wasserstein 距离 + 人体工学
  违规率 + 可视化（plot_chart 扩展连续 x，改动极小）。
- 产物直接可玩：单水平线经典下落，官谱格式 writer 现成。

### P2 — 程序化演出合成器

- 输入 P1 玩法谱 + 音频结构（能量/novelty 分段）。
- **机械求解**：给定 (hit_x, hit_y, θ, t)，构造一条线的 move/rotate
  事件使其在 t 时刻恰好以角度 θ 经过判定点——分段线性插值封闭可解；
  音符分组共享线（官谱惯例：一组音符一条线，线数不设硬限）。
- **模式库**（手写、参数化、按段落调度）：静线 / 缓漂 / 下拍旋转 /
  分裂双线 / 副歌上浮（对应勘探中 y 上浮现象）……seed 可复现。
- 永远输出合法官谱（4k_verify 扩展为 freeform_verify：事件覆盖、
  出界检查、opacity 合法）。风格有限但**保底可玩、可发布**。

### P3 — 学习式演出（在 P1+P2 之上）

- 挖掘每音符的**进场属性**：击打时线角 θ（勘探已算）、线速度、
  线归属分组——全部可从官谱精确反算，形成监督数据。
- 小型序列模型预测 (θ, 分组, 模式标签)，仍由 P2 合成器落地
  ——学的是"排演决策"，不是原始事件曲线，数据效率高一个量级。
- 备选：按音乐结构检索真谱演出模板迁移。

### P4（研究向，暂缓）
端到端事件曲线生成（diffusion over piecewise-linear curves）。

## 3. 复用资产清单

| 资产 | 无轨复用方式 |
|---|---|
| 转录编码器 / AR decoder | 复用编码器；64 位置 bin × 4 键型，369 token 词表，位置残差头 |
| chart_tokenizer + GrammarState | 已支持融合 NOTE token；人体工学间距规则待补 |
| 官谱 writer / 4k_verify | writer 现成；verify 换约束集 |
| plot_chart | 轨道带 → 连续 x 轴，半天 |
| 30 首 F1 评估 | onset 部分不变，加位置指标 |
| 4k 定轨产品线 | 保留为 POS 恰取 4 个 bin 的特例 |

## 4. 风险与对策

1. **演出学习数据薄** → P2 程序化打底，P3 只学低维决策；
2. **人体工学模型**无现成标准 → 从速度/间距双约束起步，靠试玩迭代阈值；
3. **Hold 在移动线上**（判定点随线漂移）→ P2 先限制 Hold 只排静线段，
   P3 再放开（勘探待补：移动线上 Hold 占比）；
4. 挖掘的 hit_y 高潮段上浮 → P1 忽略 y 是有意简化，P2 用段落模式补偿。

## 6. 时间约定与数据修复（2026-10-16）

定轨和无轨共用 `src/data/timing.py` 的版本
`audio-offset-post-token-v1`：

- 谱面 tick 是局部时间，32 tick = 1 拍；合并多判定线时统一到第一条线的 BPM。
- 模型使用音频时间：`audio_seconds = tick * 60 / (32 * bpm) + offset`。
  4K 数组、AR 的 cross-attention 帧位置、评估与可视化均遵守这个约定。
- AR 输入位置的时钟是**消费该 token 之后**的时钟：DT 当场推进；NOTE 和
  DUR 不推进。训练和逐步 KV-cache 推理一致。
- 线移动/旋转事件在原线的原始浮点 tick 上求值，包括 Hold 尾部；随后统一
  BPM，并分别量化 onset/end，duration = end - onset，offset 不改变持续时长。
- 转录骨架从音频帧转换成谱面 tick 时减去 offset；4K 导出也减去 offset，
  JSON 保留该 offset，避免播放时重复加延迟。音频外的骨架点会被滤掉。

本次重挖 300 首、269,639 个音符，0 失败。7 首含多线 BPM，9 首 offset 非零，
7 首玩法 JSONL 的时间发生改变。300 份单线玩法参考谱已重建，300 份 4K 音频
标签缓存已生成。4K token 往返校验 300/300 通过。原谱与已有 checkpoint 保留。

逐音符核对全部 300 首，统一 BPM 后的 onset/end 量化误差均不超过半个目标 tick，
全库最大 7.103 ms。多 BPM 的旧错误会达到分钟级，例如 `月下缭乱_IN` 的 onset
最大偏差约 276.343 秒。原谱坐标和原生时刻仍用于几何求值。
free-x 的 64-bin 编码保留 264,872 个音符，4,767 个（约 1.77%）被同 tick/bin
去重；这属于位置表示损失，仍需后续设计处理。详细核对结果存于
`out/timing_audit.json`；104 项测试通过。

每份 `data/gameplay/<song>.jsonl` 带 `.meta.json`，记录时间版本、目标 BPM、
offset、原谱与 JSONL 的 SHA-256。free-x 训练会拒绝缺失或不匹配的元数据，
原谱仍在记录路径时也校验原谱 hash。全库统计在 `data/gameplay/manifest.json`。
4K chart cache 的键包含时间版本、谱面内容 hash 和转换参数；旧 mel cache 可复用。

重新挖掘、验证：

OMP_NUM_THREADS=1 MKL_NUM_THREADS=1 MPLCONFIGDIR=/tmp/audiolab-mpl \

## 7. 有资源限制的双路线训练

`script/train_models.py` 串行执行：转录器 → 4K 解码器 → free-x 解码器 →
两套 30 首验证谱面生成 → 25/50/92.9 ms 容差评估。GPU 默认使用物理编号 1；
在设备受限的沙箱内看不到 GPU 时，需在获得授权后于沙箱外运行。

```bash
.venv/bin/python -m script.train_models --preflight
.venv/bin/python -u -m script.train_models
# 仅在队列已停止时恢复；同一 run 的 epoch 配置须保持一致
.venv/bin/python -u -m script.train_models --resume-run
```

输出默认在 `checkpoints/timing_v1/`，旧的 `checkpoints/transcriber`、`decoder`、
`decoder_freex` 作为迁移初始化来源。转录器最多 20 epoch，两个解码器各最多
30 epoch，patience=8；`--init-ckpt` 只迁移权重，重新建立优化器、EMA 和验证记录。
解码器仅迁移 decoder，encoder 使用本轮转录器的最佳权重。

资源限制：

- 只运行一个训练/生成 worker，`num_workers=0`；转录器 batch=2、累积 8 次，
  解码器 batch=1、累积 6 次。转录验证 batch=1。
- PyTorch 显存分配上限为单卡总量的 65%（24 GiB 卡约 15.6 GiB，不含驱动等开销）。
- 磁盘至少保留 8 GiB、系统可用 RAM 至少保留 8 GiB，worker RSS 上限 10 GiB。
  训练每 5 秒检查，外层监督器每 10 秒检查。RAM 是监测阈值，并非操作系统硬隔离；
  达阈值会停止队列，已写好的 checkpoint 保留。
- 每 epoch 保存一个可续训 checkpoint，成功写完再删除本轮多余中间 checkpoint，
  每个模型保留最新一个以及 best/final。采用临时文件加原子替换，写入前预留整个
  临时文件所需空间，防止写盘失败破坏已有权重。

`run.json` 记录阶段、进程与命令；`resources.jsonl` 记录资源采样；各阶段的 `.log`
记录训练和评估输出。模型子目录的 `metrics.jsonl` 也包含内存、磁盘和显存峰值。
AR 的 `train_nll/val_nll` 已修正为纯 next-token CE 的 bits/token，辅助转录和位置
损失计入 `train_loss/val_loss`，因此不能与旧版混合损失的 NLL 数值直接比较。

## 8. timing_v1 基线与生成诊断

本轮训练已完成：转录器 early stop 于 epoch 9（最佳 epoch 1，val F1=0.4359），
4K/free-x 解码器均完成 30 epoch，最佳纯 CE 分别为 2.0305/3.2425 bits/token。
默认混合生成（转录阈值 0.7、top-p=0.95、seed=42）的 30 首验证结果：

| 模式 | onset F1 @25ms | @50ms | @92.9ms | Hold 占比 | 参考 Hold 占比 |
|---|---:|---:|---:|---:|---:|
| 4K | 0.592 | 0.631 | 0.678 | 0.4% | 11.9% |
| free-x | 0.585 | 0.623 | 0.672 | 4.0% | 11.7% |

free-x 位置 F1（92.9ms、屏宽容差 0.05）为 0.190。当前能导出合法单线谱，
音频对应、位置质量与实际可玩性仍需验证；这些权重仍是开发基线。表中的 Hold
比例仅作诊断，不以接近参考比例作为稳定发布门槛。

诊断入口（固定抽取训练集样本，避免在验证集调参）：

```bash
.venv/bin/python -m script.train_models --worker script.diagnose_decoder -- \
  --samples 6 --output out/decoder_diagnostics
```

脚本对比真实上下文中的键型概率与实际生成，保存 top-p=0.95/1.0 的输出和
JSON 报告。`--teacher-only` 只做概率诊断；`--skeleton-source reference` 是真实
节奏骨架的 oracle 对照，不能当成音频生成成绩；`--snap-ticks 4` 是转录骨架的
实验性网格校准，默认关闭。Hold 概率是给定 NOTE 的条件分布，未施加语法 mask，
不可直接当成实际生成的键型比例。

报告另计静态线的近距离和弦及 Hold 期间同位置音符（屏宽距离 <0.03）；
这是输出冲突提示，尚不等价于完整人体工学或移动判定线可玩性评价。
诊断只写小型谱面/报告，复用现有数据与权重，遵守同样的资源预留阈值。

## 9. 生成退化定位与输出修复（2026-10-16）

固定抽取训练集 6 首（seed=42），两种模型分别进行完整真实上下文预测和实际
采样。下表为**训练集诊断**，不是新的验证集成绩；F1 为逐曲平均，Hold 为合计
音符占比。输出均未应用可玩性修复。

| 模式 / 采样 | Hold 占比 | onset F1 @92.9ms | Hold 邻近冲突 |
|---|---:|---:|---:|
| 4K flat p=0.95 | 0.33% | 0.7173 | 11 |
| 4K flat p=1.0 | 4.50% | 0.7015 | 296 |
| 4K type_preserving p=0.95 | 3.42% | 0.7010 | 174 |
| free-x flat p=0.95 | 4.78% | 0.6939 | 164 |
| free-x flat p=1.0 | 8.05% | 0.6804 | 276 |
| free-x type_preserving p=0.95 | 8.35% | 0.6699 | 282 |

两套参考 token 的 Hold 占比约 12.37%。真实上下文条件 NOTE 概率中的 Hold
质量分别约 12.24% / 11.01%，远高于实际采样。去掉截断或保留键型概率能恢复
一部分 Hold，但密度、节奏及冲突存在代价，所以默认继续使用 flat p=0.95。
`type_preserving` 保留为显式实验开关，不将单项键型比例改善当成整体提升。

另对同一训练曲 `Demonkin_IN` 做 4K 单曲消融：真实骨架仍仅输出 5/817 个
Hold；转录骨架吸附到 4 tick 网格后为 0/759。网格修复并未恢复 Hold；这个
小样本提示节奏误差不是唯一原因，不能据此确定具体训练改法或外推整体收益。

本轮不增加训练权重，先落实确定性输出修复：

- 4K：长条在同轨下一音符或实际波形结尾前结束。
- free-x：同刻位置采用最小平方位移投影，保持左右顺序与音符数，默认间距
  0.04 屏宽；随后在邻近下一音符前截短长条。
- 共用：达到 token 上限时若 Hold 尚无 duration，补 1 tick 后再 EOS，保证
  严格语法可解码；音频范围不包含 mel 补齐部分。
- `--raw-output` 可分离模型原始质量与后处理收益。批量修复工具不重采样，
  保留原始输入并写逐曲报告。只有静态、居中、水平单线输出适用。

30 首验证输出复核：4K 截短 40 条 Hold；free-x 移动 104 个音符（最大位移
0.01984 屏宽）、截短 335 条 Hold；两者都无 Hold 转 Tap，音符数及起点保留。
按屏宽距离 <0.03 的诊断规则，4K Hold 冲突 76→0；free-x Hold 冲突 627→0、
近距离和弦 31→0。free-x 位置 F1 0.18958→0.18965，onset F1 不变。这是
后处理结果，不是重新训练的模型提升，也尚未保证两手可达性和多线演出可玩性。

本地输出为 `out/playable_4k` / `out/playable_freex`，每套 30 首；同级
`.report.json` 为逐曲修复记录。完整采样报告在
`out/decoder_diagnostics_sampling` / `out/decoder_diagnostics_type_preserving`。
全套 136 项测试通过（含两种词表的采样概率、极限收尾和实际音频导出回归）。
本轮完成后磁盘余量约 12.5 GiB，可用 RAM 约 37 GiB；未复制数据或 checkpoint。

下一轮训练实验应以真实 rollout 的键型、密度、位置和修复率与验证 CE 联合
判断，先对历史上下文扰动或键型条件做单因素小试。当前证据不足以认定单纯延长
训练或调采样参数就能解决退化，因此不将本轮模型提升为 main 稳定版。

## 10. 音频对应优先与起点校准（2026-10-17）

用户明确：Hold 数量不是绝对目标，应与音频特征对应，键型专项训练可以后置。
后续实验优先考察音乐起点、音频条件作用、密度和可玩性，不以恢复官谱 Hold
比例作为验收条件。

同样的 6 首训练曲、相同真实 token 历史下，替换音频特征并保留时间嵌入及 mask：
4K 的整体 NLL 从 1.8758 升至 1.9634 bits/token（错歌）；free-x 从 2.9183
升至 3.0456。反转特征时间顺序、清空声学特征也使整体损失上升。说明声学条件
有作用，但这里是真实上下文敏感度测试，不能等同于实际生成的听感质量。

转录骨架新增基于亚帧时间与置信度的 NMS。32 首训练曲上选择阈值 0.7、最小
起点间隔 35ms，配置冻结后在独立 30 首验证曲上评估：

| 唯一起点指标 | 原阈值模式 | 加 35ms NMS |
|---|---:|---:|
| F1 @25ms | 0.6626 | 0.6920 |
| Precision @25ms | 0.6402 | 0.7019 |
| Recall @25ms | 0.7021 | 0.6981 |
| F1 @50ms | 0.6994 | 0.7279 |
| 起点密度 / 参考 | 1.1235 | 1.0218 |
| 平移对照 F1 @25ms | 0.2688 | 0.2692 |

这里同刻和弦只计一个起点，采用按时间的最大匹配数量，不与前文整谱多音符 F1
混用。NMS 是候选起点去重，不吸附节拍网格。
生成入口可显式传 `--onset-threshold 0.7 --onset-min-interval-ms 35`；原默认保留。

复现入口为 `script.calibrate_skeleton --phase fit`，随后用 `--phase evaluate
--calibration <fit-report>` 和独立数据列表验证。报告记录参数选择、逐曲分数和
资源使用；拒绝训练校准曲与验证曲重叠。

固定 seed=42 抽取 6 首验证曲，AR 权重与 flat top-p=0.95 不变，替换为上述
NMS 骨架后，整谱多音符 F1 @25ms：4K 为 0.5933→0.6016，free-x 为
0.5851→0.5894；音符总数分别为 6,172→5,851 和 6,664→6,321。
这里只比较相同 6 首曲目，尚不能当作全 30 首整谱结论。原谱与诊断报告分别在
`checkpoints/timing_v1/eval_decoder*`、`out/decoder_nms35_val6/report.json`。

## 11. 独立全局节奏模型（2026-10-17）

新增与位置、键型无关的 onset/offset 预测头，输出分辨率为 mel 帧（约 23.2ms），
供定轨和无轨解码器共同使用。和弦的同刻音符只标一个起点；音频末尾之后的帧
不计损失。v1 冻结原编码器，仅训练 33,412 个参数，8 epoch；v2 从 v1 开始，
头部学习率 1e-4、编码器学习率 1e-5，再训练 8 epoch。独立目录保存权重，旧模型
不覆盖。v1 的原编码器张量逐项核对没有变化；v2 的原四轨分类头不参与训练，
因此 v2 应作为全局节奏模型使用，不作为重新校准过的四轨转录器。

先用固定 32 首训练曲选择参数，再冻结参数评估 30 首验证曲。初始校准网格为
阈值 0.1 到 0.9、步长 0.1，以及间隔 0/15/25/35ms。这里的验证集也用于选取
最佳训练 epoch，属于开发验证集，不是最终未使用测试集。

| 骨架 | 阈值 / 间隔 | 唯一起点 F1 @25ms | Precision | Recall | 起点密度 / 参考 |
|---|---|---:|---:|---:|---:|
| 原转录器 | 0.7 / 0ms | 0.6626 | 0.6402 | 0.7021 | 1.1235 |
| 原转录器 + NMS | 0.7 / 35ms | 0.6920 | 0.7019 | 0.6981 | 1.0218 |
| 全局 v1 | 0.2 / 35ms | 0.6980 | 0.6798 | 0.7362 | 1.1146 |
| 全局 v2 | 0.2 / 25ms | 0.6983 | 0.6739 | 0.7441 | 1.1356 |

v1 最佳 epoch=8，验证 loss=0.279891；v2 最佳 epoch=7，loss=0.274748。
v2 相对 v1 的起点 F1 收益很小且密度更高，不凭 loss 下降直接替换默认模型。
进一步仅在同一 32 首训练曲上细化阈值（0.15 到 0.35，步长 0.025）与间隔
（15/25/35/45ms），选出 0.25 / 25ms。冻结后，30 首验证曲的起点 F1 @25ms
为 0.6976，Precision=0.7095、Recall=0.7048、密度比=1.0193；相对粗网格
明显减少冗余。相对原转录器 + NMS 的 F1 差为 +0.00557，逐曲配对 bootstrap
10,000 次、seed=42 的 95% 区间为 [-0.00175, 0.01136]，23/30 首提高。
区间包含 0，当前不能断言学习到的节奏头已稳定优于原转录器 + NMS。

Hold 比例不参与训练损失、参数选择或
新旧模型验收。后续键型专项可以结合持续能量、衰减、起止边界等声学证据训练，
在当前阶段优先完成节奏与位置/轨道生成的可用性验证。

原始报告位于 `out/global_rhythm_calibration_{train32,val30}/report.json`（v1）及
`out/global_rhythm_v2_calibration_{train32,val30}/report.json`（v2 粗网格）；细化报告为
`out/global_rhythm_v2_refined_{train32,val30}/report.json`。v2 训练约
250 秒，进程 RSS 约 1.52 GiB，显存分配峰值约 1.58 GiB、保留峰值约 1.80 GiB；
训练结束剩余磁盘约 12.33 GiB、可用 RAM 约 37.38 GiB。没有新增全量特征缓存，
每个实验只保留 best/last/final 三个 checkpoint。
