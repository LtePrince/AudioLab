# 旧音频条件审计：可复用部分与 v2 修正范围

2026-10-17 只读审查 `script/audit_audio_conditioning.py`、`TokenChartDataset`、encoder／decoder 时间与 mask，以及 `out/audio_conditioning_train6/report.json`。没有重跑训练或 GPU 实验。结论：可复用固定 teacher-forcing 历史与分项评分框架，不能原样作为当前产品整曲或音乐质量验收。

## 历史证据的准确含义

旧报告为训练集 6 曲，每条路线分别比较 matched／reversed／wrong_song／no_audio。按各项 token 数重新加权，得到以下变化；不是对旧模型的重测。

| 模型 | matched all bits/token | reversed − matched | wrong_song − matched | no_audio − matched |
| --- | --- | --- | --- | --- |
| 4K decoder | 1.87576 | +0.06256 | +0.08763 | +0.10343 |
| free-x decoder | 2.91832 | +0.09410 | +0.12726 | +0.16484 |

这些历史值支持“给定真实 token 历史时，匹配声学特征的参考预测损失较低”的有限观察。报告没有源码、权重和输入哈希，无法追认精确版本；数据用于训练，不是独立泛化、完整生成、声学准确率或人类偏好证据。两模型的词表与参考事件不同，不能用两行 bits 大小比较玩法优劣。旧运行记录的 RSS 为 1.488 GiB、PyTorch reserved 峰为 0.316 GiB，不是新整曲实现的预算证明。

## 当前脚本的解释与边界

| 项目 | 实际行为及影响 |
| --- | --- |
| 音频范围 | 固定 8192 mel 帧／4096 memory 帧，对应约 190.218 秒。长曲被截断；标签按音符头是否位于该范围筛选，跨尾 Hold 的持续仍可进入评分。须报告截断／排除，不能称完整音频对照 |
| 此历史样本是否截断 | 只读音频头与参考谱确认，六首为 127.943～168.033 秒，没有头／Hold 尾越过 190.218 秒。因此长曲问题是脚本推广限制，不能误写成这六曲已被截尾 |
| 短曲填充 | mel 先按自身最小值补到 8192。encoder 是无 padding mask 的全局 attention，短曲特征已经吸收填充上下文；decoder 的后置 mask 不能撤销它。与当前产品仅补到步长倍数的整曲布局不同 |
| 尾部有效长度 | `mel_frames // 2` 取整会漏掉奇数尾段；六曲中五份缓存的 mel 帧数为奇数。v2 应从真实音频秒与产品一致的特征时间轴判有效，不能把缓存形状直接当完整音频范围 |
| mask fallback | 审查时的 `cross_mask` 空局部窗口 fallback 只在 `[0,T−1]` 找最近帧，可能重新允许无效 padding。CPU 小模型已复现：valid 仅 0／1／2、token frame=6、window=1，结果允许 key=6。独立修复 `5a6877a` 改为最近真实有效帧、同距取较早帧、无任何有效帧明确拒绝；当前产品全有效内存路径不受原反例影响 |
| reversed | 反排的是编码后的、已上下文化的有效特征，不是倒放波形；仍含同曲上下文。应命名为 `encoded_feature_reverse` |
| wrong_song | 将另一曲有效特征线性插值为目标长度，包含时间拉伸。`align_corners=False` 的源索引约为 `(j+0.5)*Lsrc/Ldst−0.5`，边缘另有取值行为；要记录长度／映射。按列表索引选另一行不能保证音频内容不同，需核对音频哈希 |
| no_audio | 在 `prepare_memory` 前置零声学特征；后续投影偏置、memory 时间嵌入和真实 token 历史仍在。应称 `zero_acoustic_features`，不是完全无条件模型 |
| 分项分数 | all／DT／NOTE／DUR 是参考 token bits；note_type 与 position 是“下一项为 NOTE”条件下的边缘分类损失，不可与 all 直接相加。DUR token 数也不等于 Hold 数 |
| free-x 精度 | 只评价 64 档位置 token，没有评价连续 offset head。不能据位置 bits 声称连续位置改善 |
| 标签与缓存 | 4K 来自派生四位置谱，free-x 来自带时间／源谱校验的挖掘 JSONL，再经量化和同 tick/bin 去重；都不是声学真值。mel 缓存键含路径／参数而不含音频内容哈希；缺音频还会退回零 mel，审计必须禁止这种替代 |
| 完成与资源 | 报告逐曲覆盖写，没有完整状态、文件指纹和新目录隔离。资源只在阶段间检查，不能用旧小样本峰值保证更长 teacher-forcing 的 L² attention 开销 |

teacher forcing 固定了真实动作历史，有助于降低采样分歧，但强历史信息也可能掩盖音频的贡献。小差值不能直接解释为模型“不听音乐”；分数变差也不自动证明可玩性差。

## 可执行的最小 v2

1. **先固定输入与边界，不换模型。** 新输出目录、版本 schema、完整／失败状态；记录源码、权重、音频、谱面／挖掘元数据哈希及逐曲分母。先读少量开发曲并明确不是冻结测试；错曲配对必须不同音频哈希。缺失音频、来源不明缓存、越音频时间的标签明确失败或进入排除清单。
2. **与当前产品共享时间和布局编码口径。** 复用 `load_audio` 的整曲特征／真实时长与 full 布局的最小步长补齐、资源预检；不用固定 8192 截曲或给短曲补几十秒。保留旧 fixed-padding 为明确的历史条件时，分开输出，不能混报。每条布局权重带自己的 encoder；共享候选 NPZ 的特征来自另一权重时不能直接替代布局特征。
3. **保留已有负对照，修正名称与映射。** matched、编码后特征反排、异曲特征时长映射、声学特征置零先足够。token 历史、绝对秒时间、时基、有效区间保持相同；记录每种映射。不同干预分列，不能称波形倒放或端到端错音频实验。
4. **保留 bits 并补足 free-x 的条件 offset 误差。** 返回同一 forward 的 NOTE hidden，按真实 bin 的 offset 掩码计算条件亚格误差，同时保留位置 bin bits。按键型／持续 token 给出样本数与逐曲差值，Hold 仍不设配额。offset 条件误差不是完整采样位置误差。
5. **先验边界，再跑少量开发曲。** 合成验证奇数尾部、超过旧上限、非零 offset、跨尾 Hold、缺输入／同音频错曲、mask 空窗与全无效输入。teacher-forcing 也要预估 token self-attention 和 logits 资源；不够则明确失败，不能悄悄截 token。先做一次小规模串行运行，有结果再扩大，不重跑旧训练六曲来补不存在的版本证明。

共享 mask 修复与审计 v2 分开提交；F4a 可以继续。此批完成后才开展 [K2／F2 协议](model_quality_protocol.md)中的固定候选真实生成对照，以及取音和修复分离。该 v2 是参考条件诊断，不替代玩家完整试玩。

`5a6877a` 的 decoder 测试由设计 agent 独立通过 25 项（4.98 秒）：非前缀有效帧、边界／并列选择、无有效输入拒绝，以及 4K／64-bin 的全前向和增量 step 对无效 memory 的大幅扰动保持 logits 不变。主会话集成后全套 249 项通过。这仅验证 decoder 屏蔽；固定填充对 encoder 的上下文污染仍属于 v2 待修范围。
